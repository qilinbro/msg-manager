# 飞书本人私聊早晚报：本机启用与验收

- 日期：2026-11-17（Asia/Shanghai）。
- 关联：`CHG-T12-003` / `CHG-T13-005` / `CHG-T16-001` / `CHG-T17-001` / `CHG-T20-004` / `CHG-T21-004`。

本文说明本轮飞书早晚报的配置、授权和验收边界，**不表示新版本已部署，也不表示真实飞书发送、模型效果或手机通知已验收**。后端待 joey 审查，前端待 angjustinl 审查，kirinbao 组织真实验收；实际完成日期仍为 —，MVP / 扩展完成统计仍为 **0 / 27、0 / 5**。进度以[功能记录](<../feat.md>)、[任务卡](<../任务规划.md>)和[技术文档](<../技术文档.md>)的实际记录为准；架构取舍见 [ADR 0015](<adr/0015-feishu-private-digests.md>)。

## 1. 支持什么，不支持什么

- 使用**同一企业租户内的自建应用机器人，向本人固定私聊发送纯文本摘要**。不是群机器人 Webhook，不读取飞书聊天，不向群、外部联系人或任意收件人群发，也不开放通用会话自动回复。
- 自动计划默认关闭。手动“生成预览”只授权模型处理；“发送这份预览”需要另一份明确同意。启用自动计划则另行授权后续窗口持续调用模型并发送，不会每次再弹确认。
- 固定北京时间 **08:00、20:00**，不受浏览器时区影响；本版不提供任意时间设置。只处理相邻固定时点之间已完整结束的半开 12 小时窗口：

| 时点 | 内容窗口（Asia/Shanghai） |
|---|---|
| 当天 08:00 | `[前一天 20:00, 当天 08:00)` |
| 当天 20:00 | `[当天 08:00, 当天 20:00)` |

结束时点上的消息属于下一个窗口。手动预览也使用后台时钟确定的最近完整窗口，不能指定日期补跑或改成滚动 24 小时。

旧 `digest24h` 日报仍是独立的本地预览链路，不能用它触发飞书发送。飞书这条有限发送通道不代表 QQ、微信、邮箱或通用审批/发件箱已开放发送。

## 2. 先在飞书侧由本人准备

以下操作由应用所有者在自己的飞书和开发者后台完成；不要把 App Secret、原始 Open ID、令牌或真实聊天粘贴到助手对话、提交记录或截图中。

1. **确认租户和应用类型。** 在飞书开放平台创建企业自建应用，并启用机器人能力；本人飞书账号与应用处于同一企业租户。外部成员、外部群、自定义群机器人不在本版范围。
2. **申请最小发送权限。** 为应用申请并按企业流程批准 `im:message:send_as_bot`（以应用身份发送消息）。本产品不需要读取消息、获取已读用户、用户登录或通讯录批量查询权限。不要为解决配置问题随意增加权限。参阅[应用权限说明](https://open.feishu.cn/document/server-docs/application-scope/introduction.md)和[发送消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/create.md)。
3. **发布并保证本人可用。** 按企业审批流程发布包含机器人能力、权限和可用范围的新版本，将本人纳入应用可用范围；有额外管理员控制时一并完成。仅在后台勾选权限、保存草稿或复制 App ID，不代表权限已生效。参阅[应用可用范围](https://open.feishu.cn/document/home/introduction-to-scope-and-authorization/availability.md)和[可用范围额外控制](https://open.feishu.cn/document/platform-notices/breaking-change/app-availability-range-additional-control.md)。
4. **准备三项本机输入。** 从该自建应用后台取得 `App ID`（`cli_…`）及 `App Secret`；取得**该应用下本人的 `open_id`**（`ou_…`）。不能用群 ID、`user_id`、`union_id`、手机号或另一个应用下的 Open ID 代替。
5. **只复制本人 Open ID，不代发测试。** 官方[获取用户 ID 指引](https://open.feishu.cn/document/platform-overveiw/basic-concepts/user-identity-introduction/open-id.md)提供 API 调试台“发送消息 → receive_id_type=open_id → 快速复制 open_id”的可视化选择方式。选中本应用和本人，仅复制标识；这一步不需要在调试台点击真实发送。本产品不会替你枚举联系人或按手机号查询。
6. 在本人飞书中找到并打开正确机器人的会话，以便后续人工对账。平台可向可用范围内用户主动发送，但能找到机器人、已有会话或做过互动，都不能代替权限、目标归属和真实发送验收。参阅[机器人使用说明](https://open.feishu.cn/document/client-docs/bot-v3/how-to-use-bot-in-feishu.md)。

本产品仅出站获取应用令牌、发送文本，**不用开放公网服务，不用配置群 Webhook、消息事件订阅或用户 OAuth 回调**。不要把本机 API 暴露到公网。

## 3. 在本机保存配置

1. 按[工作台连接说明](<unified-inbox.md>)连接已获授权、带本轮实现的本机后台，启用 SQLCipher 加密消息库；模型配置见[模型接入说明](<ai-setup.md>)。阅读本文不会升级或重启正在运行的实例。
2. 打开左侧 **飞书早晚报 → 人工配置自建应用与本人 Open ID**。本人填写 App ID、App Secret 和完整本人 Open ID，核对所属应用与租户，勾选保存同意，再点 **保存本机配置**。
3. 保存只写本机加密库，**不调用飞书或模型，也不验证 Open ID 归属**。状态只返回 App ID、密钥是否存在、脱敏目标、配置版本与绑定标识；`recipient_ownership_verified` 保持 `false`。`configured:true` 只说明三项已保存，不能当成“本人身份/权限已验证”。
4. App Secret 和原始 Open ID 不经 GET 取回、不写浏览器持久存储、不交给模型。表单中的敏感输入在每次保存结束（含失败、未知和停止等待）、重新读取或离开页面后清空；不要用真实凭据录屏或截图。
5. 修改配置时仍须重新填写完整本人 Open ID。只有 **App ID 未变、已有密钥、提交的 App Secret 为空且显式勾选沿用**时，`retain_secret:true` 才能保留原密钥；空输入本身不表示沿用。换 App ID 必须重新填密钥。

**每一次保存飞书配置或模型配置，即使值看似没变，也会撤销原自动计划授权。** 配置清除亦关闭计划。必须重新读取当前版本、核对目标并重新同意，不能通过 A→B→A 换回旧值恢复旧授权。配置与计划各有独立 CAS 版本，冲突时先只读刷新，不能自动重复提交。

## 4. 先预览，再独立决定是否发送

1. 核对页面上的模型名称、目标地址、模型 ID / 版本、共享额度、脱敏本人目标和 12 小时窗口。
2. 勾选**本次模型数据处理同意**，点 **生成最近完整窗口预览**。这会把符合规则的已入库会话文本交给所示模型，可能收费，但**不授权飞书发送**。
3. HTTP 202 / `running` 只表示后台已占用记录。使用 **重新读取**或**只读获取报告**等待最终状态，不能再次提交生成。每个窗口只有一次生成尝试：成功、失败、未知、仍在运行都占用该窗口，没有 `force` 或失败后重算。
4. 仅 `succeeded` 报告可供发送。仔细核对 **将实际发送的完整正文**、候选待办、来源证据、截断标记、本人目标、窗口和版本。`content_hash` 绑定报告 ID、窗口、完整发送文本与模型/飞书绑定，不只是裸正文的哈希。未显示在冻结正文中的内容不会临时拼入发送。
5. 如愿真实发送，另行勾选**本次飞书发送同意**，点 **发送这份预览至本人飞书**。只发送服务器持久化的这份正文；请求不能换收件人、修改文本、换 URL 或让模型自填任意正文。
6. 用报告/投递编号只读查询结果。手动发送授权到**下一固定时点**失效，例如当天 08:00 窗口报告只能在当天 20:00 前发送。过期不补发；换配置、换模型或暂停再恢复来源后，旧报告也不能重新获得发送权限。

不要把“报告已生成”当作“消息已发送”。生成报告和投递回执是两份独立状态；发送响应丢失时，报告的 `delivery` 字段可帮助找回已有投递，而不是重新发送。

## 5. 确认后才启用固定早晚报

在 **固定早晚报计划**区域，分别核对并勾选：

- **持续模型处理同意**：后续各固定窗口将符合规则的未暂停入库文本交给所示模型，可能产生费用；绑定模型 ID 和版本。
- **持续飞书发送同意**：后续自动向已保存的本人私聊发送冻结摘要与待核对待办，不逐次询问；绑定飞书配置版本和目标。

两项都同意后点 **启用固定早晚报**，确认“下次窗口结束”、计划版本和已授权绑定。启用只从**未来的下一个时点**开始，不立即补发上一个窗口。

- 后台依赖主机开机、联网、未休眠且服务存活；关闭工作台窗口不等于停止独立后台，关机/休眠则不能保证执行。
- 自动调度只在正常运行时允许时点后的 **2 分钟启动宽限**。主机恢复、服务启动或超过宽限时跳过旧时点，不补齐离线窗口、不把积压任务排队稍后重发。宽限不是网络重试许可；已占用的报告/投递不自动再做。
- 想停止后续自动处理，勾选关闭同意并点 **关闭后续计划**；不再使用时可另行 **清除配置并关闭计划**。这两项不依赖模型就绪或剩余额度。
- 关闭、清除或暂停来源会取消尚可取消的工作，并通过后端派发屏障阻止确认后的新外呼；**不能保证撤回已开始的外部请求、平台已接受的消息或已交给模型的数据**。关闭计划也不会删除历史回执。

## 6. 内容范围、费用与隐私

- 本通道只分析窗口内**已经入库且未暂停 AI**的私聊/群聊文本，不替平台补收历史，不上传附件正文，不推断尚未建模的群成员权限。没有候选不等于没有重要事项。
- 相关性是固定启发式筛选（阈值至少 3），不是已经过真人评测的语义分类。至多 500 条候选，最多 4 个相关会话、每会话最多 20 条；正文和模型输入还受字节预算裁剪，不承诺覆盖整个窗口。
- 按会话独立调用已有 `Analyze`，不把不同联系人上下文混成一个模型输入；本地聚合经校验的摘要。**待办来自后端按原文与证据形成的候选，标注“待人工核对”**，不是把模型回复草稿 `Draft` 冒充待办，也不是已创建/执行的任务。
- 分析、档案、旧日报、Agent 和飞书共用上海自然日模型额度及单并发 gate，默认每天 50 次（界面可设 1—1000）。每个会话的实际模型尝试分别先占本机额度，失败也计数，重启不清零；供应商是否收费以其规则为准，不是“一份早报只算一次”。服务忙且尚未占窗不等于失败后重试许可。
- 报告持久化所有模型输入会话的 `source_refs` 与 AI 设置版本，不仅是最终展示的少量摘录。读取报告、后续模型派发及发送前重验完整来源、模型、配置和目标；来源被暂停、删除或版本变化，或绑定发生变化后，旧正文不可重读或外发。暂停后再恢复仍不能复活旧正文。最小投递元数据可继续只读人工核对。
- 发送正文先作 UTF-8 与双层 JSON 预算裁剪，出现省略时显式提示；本机报告正文上限 8000 字节，连接器文本上限 12000 字节、完整飞书请求上限 16384 字节。引号、反斜杠、换行等经两次 JSON 编码，不能只按可见字数估算。主动 `<at>` 标记会失活，避免原始聊天文本触发机器人提及。
- App Secret、应用访问令牌、原始接收 Open ID 和本机鉴权凭据不提供给模型/工具参数或结果；错误只返回固定安全分类，不回显上游错误正文。聊天、摘要、证据及回执仍是敏感业务数据，应保护本机数据库和导出材料。

## 7. 回执、失败和人工核实

| 投递状态 | 可信含义与下一步 |
|---|---|
| `running` / HTTP 202 | 已受理但未确认结果；只读查回执，不再次 POST。 |
| `succeeded` | HTTP 2xx、明确存在 `code=0` 且取得 `message_id`，只证明**飞书平台已接受**。 |
| `failed` | 已知未成功或在发送前被阻止；本窗口也不开放重发。修正配置后核对新授权，等待未来窗口。 |
| `unknown` | 可能已经产生外部效果；去本人飞书人工核实，不盲目再发，不把它当作失败回滚。 |

消息发送阶段断网、超时、5xx、无法验证的 JSON / 缺少成功字段、响应丢失，或平台 `230049`（发送中）均可能进入 `unknown`；服务启动将遗留的 `running` 报告/投递收敛为 `unknown`，不自动重放。获取令牌阶段失败还没有提交消息，与发送后结果未知不同，但同窗口仍不自动再尝试。

常见安全错误及排查方向：

- `FEISHU_AUTH_FAILED`：由本人核对 App ID / Secret、应用有效性及后台授权，不在对话里贴凭据。
- `FEISHU_PERMISSION_DENIED`：检查机器人能力、最小发送权限、审批及发布版本。
- `FEISHU_RECIPIENT_UNAVAILABLE`：核对本应用下本人 Open ID、可用范围、本人账号状态、是否停用/屏蔽机器人。
- `FEISHU_RATE_LIMITED` / `FEISHU_QUOTA_EXCEEDED`：分别核对瞬时限制或应用月额度；429 不一定只是短暂拥塞。**本产品不按 Retry-After、刷新令牌或修复配置自动重发这份消息。**
- `FEISHU_CONFIG_CHANGED` / `FEISHU_MODEL_CHANGED` / 来源变更类错误：只读刷新当前绑定和回执，不能复用旧正文/同意。

平台成功、桌面客户端出现消息、手机收到系统通知、用户已读是**不同验收项**。手机飞书登录、会话免打扰、飞书客户端通知、系统权限和省电策略都要本人分别核对；本文不承诺系统通知必达。已读查询是[独立 API](https://open.feishu.cn/document/server-docs/im-v1/message/read_users.md)，本版不申请它的额外权限，也不查询已读。

## 8. 本机 API 与 Agent 边界

全部沿用本机 Host / Origin / Bearer / 工作区认证，基础路径 `/api/v1/feishu`：

| 方法 | 子路径 | 用途 |
|---|---|---|
| GET | `/status` | 本地脱敏状态，**不联网核验**。 |
| PATCH | `/config` | 人工保存完整配置及 CAS，Agent 禁用。 |
| DELETE | `/config` | 人工清除配置及 CAS，Agent 禁用。 |
| GET | `/schedule` | 读取固定计划。 |
| PATCH | `/schedule` | 启停计划；启用需当前绑定与持续同意。 |
| POST | `/preview` | 生成最近完整窗口，不接受调用者指定窗口。 |
| GET | `/reports/latest` | 只读取最新报告或 `null`，校验正文隐私与绑定。 |
| GET | `/reports/{report_id}` | 只读取指定报告，同样校验。 |
| POST | `/reports/{report_id}/send` | 仅发送服务器报告及匹配的 `content_hash`。 |
| GET | `/deliveries/{delivery_id}` | 只读投递最小元数据，便于结果未知时核实。 |

本机 JSON 请求限制 **8192 字节**，与飞书出站请求的 16384 字节限制不是一回事；严格拒绝未知字段、重复字段、非标准大小写、`null` 和额外查询参数。配置 CAS 与计划 CAS 均从 1 起；未启用计划的 `config_revision:0`、仅环境配置模型的 `model_config_revision:0` 均可合法出现，不能当作已授权绑定。

原生 Agent 增加上述 8 项非凭据业务操作；凭据保存/清除仍仅限本人专用表单。所有 Agent mutation 都先展示不可变的后端操作预览，逐项确认、5 分钟有效、只消费一次，并重验当前模型数据同意；**发送或启用计划还需独立勾选飞书外发同意**。模型不能借工具改目标、读密钥或绕过报告/来源校验。既有确认协议见 [ADR 0014](<adr/0014-native-assistant-and-confirmed-business-tools.md>)。

## 10. 官方协议与限制依据

公开文档核对日期为 2026-11-17。权限名称、控制台流程和额度可能调整，以本人应用后台实际审批和当时官方说明为准，不用本文代替平台授权。

- [当前应用访问令牌](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token.md)：本轮固定使用 `POST https://accounts.feishu.cn/oauth/v3/token`，表单四字段 `grant_type=client_credentials`、`client_id`、`client_secret`、`scope=im:message:send_as_bot`；读取 `access_token` / `expires_in`，令牌为 JWT，不假定旧前缀或固定长度，只在后台内存缓存。不要求用户手工获取/填写访问令牌，也不回退到[历史 internal token 接口](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal.md)。
- [发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create.md)与[文本内容结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json.md)：固定 `receive_id_type=open_id`、`msg_type=text`；`content` 是序列化后的 JSON **字符串**。`uuid` 最长 50 字符，官方去重有效期仅 1 小时，不能代替本机长期账本。官方文本请求限制 150 KB，本项目主动采用更保守预算。
- [频率限制](https://open.feishu.cn/document/ukTMukTMukTM/uUzN04SN3QjL1cDN.md)、[机器人 FAQ](https://open.feishu.cn/document/server-docs/im-v1/faq.md)和[通用错误](https://open.feishu.cn/document/ukTMukTMukTM/ugjM14COyUjL4ITN.md)：发送接口文档列出 1000 次/分钟、50 次/秒、同一用户 5 QPS 等限制，但本通道不会靠重试追赶这些上限。
- [自建应用 API 月额度公告](https://open.feishu.cn/document/platform-notices/platform-updates-/custom-app-api-call-limit.md)：公告含时限性调整，不能从旧公告推定本人的当前可用额度；请以实际控制台为准。
