# Agent 助手：使用与权限边界

关联 `FEAT-T08` / `FEAT-T10` / `FEAT-T11` / `FEAT-T12` / `FEAT-T13`；更新2026-11-18。本功能分支已接入原生工具调用，工程验证与指定审查/真实验收分别登记；**不是已部署到现有运行实例的声明**。

## 开始使用

1. 按 [工作台连接说明](<unified-inbox.md>)连接本人本机服务。原“记住设备”仍使用不可导出私钥；模型密钥不在助手里填写。
2. 在设置的模型配置中人工保存支持 Chat Completions **原生 tools/tool_calls** 的模型。只支持普通文本/JSON 回复的服务不能冒充工具调用服务。保存模型不会立即外呼。
3. 打开左侧或顶部 **Agent 助手**，查看模型名称、目标地址、今日额度和 API 权限目录。它是可关闭的工作区，不替换当前业务页；按 Esc 或关闭后保留当前业务选择和页面内存中的助手草稿。未配置/服务不可用时如实显示，不提供假对话。
4. 消息或微信来源区的求助按钮会先展示最小筛选上下文，不会自动取正文或外呼。明确 **确认带入草稿** 或 **追加到现有草稿** 后再输入/编辑任务；不会覆盖已有草稿，待确认或结果未核实时不能带入新问题。单轮请求最多8000个UTF-8字节（不是8000个汉字），不会静默截断。
5. 核对数据范围和费用，勾选本轮模型数据同意，再发起。用户问题、既有助手上下文、所请求的未暂停业务数据及工具结果可能发给展示的模型服务；不愿外发时不要提交。

例如可以要求“查看当前连接状态”“整理这个会话的待核实信息”“把此会话标为已读”。这些只是任务示例，**不是已执行记录**；执行什么由真实模型选择，是否成功以工具回执而非模型文字为准。

## 可调用范围

助手使用固定业务工具，对应现有消息/会话/导入、连接器读取与同步、AI 分析/设置/记忆、档案/事实/关联、日报等已实现接口。权限目录逐 method/path 对照现有契约：73 项中 53 项可执行（51 项业务和 2 项健康检查）、7 项仅人工、13 项未实现；另 5 项助手控制接口不递归开放。新增静态模型预设读取不返回凭据、不探测供应商，配置流程及固定来源见 [模型预设与 API 范围](<model-provider-presets.md>)。已计入飞书本人早晚报的 8 项受限操作和 2 项人工配置，见 [飞书接入边界](<feishu-setup.md>)。界面按“可读取 / 逐项确认 / 仅限人工 / 尚未实现”区分；目录覆盖不表示全部项目都可由模型执行。QQ 仅使用 Milky 1.3，已取消的 OneBot 不向模型开放，旧文档仅供历史查阅。

- **读取**：在当前轮明确同意范围内读取未暂停的业务数据。
- **逐项确认**：修改本地数据、导入、同步、模型分析、启用后台读取/计划，以及 Milky 账号核验等副作用操作，必须先展示后端固定预览。
- **人工专用**：主令牌/设备注册撤销、模型配置修改、飞书应用凭据和本人收件人配置，不交给模型。
- **尚未实现**：占位 API 和 QQ/通用发送链路不伪装可用；飞书本人早晚报是另行授权的窄范围发送能力，不开放任意收件人或正文。

搜索工具支持会话 `conversation_kind=private|group` 与 `q`，以及会话内仅匹配正文的 `q` / 向前分页；类型、平台、分类、未读/归档等条件取交集，关键词按字面匹配。没有省略参数绕过限域或用其他会话游标的能力。人工可以在业务页面查看 AI 已暂停的会话，助手仍受额外的 AI 暂停屏障。

没有任意网络请求、主机命令、SQL 或文件系统工具，也不会把模型或平台凭据给模型。QQ 及通用自动发送仍关闭；飞书本人早晚报默认关闭、需另行独立授权。模型无法通过文字要求绕过这些边界。

## 确认、拒绝与暂停

预览展示操作名、method/path、确认编号、有效期、**完整固定参数**及副作用。不能在确认请求里偷偷换目标或内容；需要修改时拒绝后另发任务。

每项确认默认未勾选。核对后仅确认这一项及其后续模型处理，不能批量“一次全开”。拒绝只提交确认编号，不调用模型。确认有效期 5 分钟，后端最终判定过期/身份/模型版本；重复点击不会二次执行。

已暂停 AI 的会话不能被助手读取或处理，会话列表会过滤它。任何来源后来暂停，助手不会把已缓存的相关历史继续发给模型；但无法撤回已经发送的数据。恢复 AI 本身也要单独确认。全局/历史摘要可能包含暂停来源，因此部分全局操作会保守拒绝；人类仍可使用原业务页面查看。

## 中断和结果未知

- `running` / HTTP 202 不表示完成；`awaiting_confirmation` 表示还没执行待确认项。
- 已拿到运行编号时，使用 **读取运行结果**。这是只读 GET，不重新调用模型或重放变更。
- 首次 POST 断网且尚未收到运行编号时，前端无法找回未知编号；不要盲目再次提交，先去业务页核实实际结果。
- **本地停止等待**不保证停止后台，也不保证撤回已完成操作。
- `unknown` / “结果未知，需核实”不是失败回滚，也不是成功。先只读检查相关业务状态，人工核实后再决定新任务。请求不会自动重发。
- 会话/运行只在当前后台进程内保留约 30 分钟，过期/重启后不可恢复。助手草稿和未核实提示只保当前页面内存，导航可保留，刷新不是持久任务恢复。

设备认证短令牌自动刷新沿用既有规则：只读最多一次重试，变更不自动重放；模型供应商鉴权失败不应让工作台忘记设备。

## 本机 24 小时日报与共享额度

分析、档案整理、日报和助手共享每日模型额度（默认 50，设置范围 1—1000；Asia/Shanghai 自然日），每次尝试先占用，失败也计数，重启不清零。

**立即生成**和**每日计划**是两份独立同意。每日同意明确覆盖每天把过去 24 小时、未暂停且已入库的有界文本发给显示的目标及可能费用。迁移会关闭旧版无绑定计划；每次保存模型配置也撤销周期同意，需要重新启用。模型不可用时仍能关闭计划。

本节的 24 小时本机日报每天最多一份运行记录：成功、失败、未知、仍运行都不自动重发，force 也不能覆盖。同日已有失败请查看错误并人工核实，不能承诺当天重试；报告只在工作台展示，不向平台发送。

飞书本人早晚报是另一项默认关闭的窄授权能力：北京时间 08:00 / 20:00、固定 12 小时窗口，生成预览、单次发送和周期外发分别同意，不将普通日报授权沿用为发送授权；见[飞书接入说明](<feishu-setup.md>)。
