# 统一消息中心使用说明

当前可以统一管理 QQ、微信、Telegram、闪聊的**已导入文本记录**，以及微信本地库读取和通过 IMAP 手动同步的邮件：按来源搜索、查看历史、标记已读/未读、置顶、归档和恢复。不同来源与账号分开保存，同名不会自动合并。微信可明确选择私聊或群聊开启后台定时只读，群会话以 `conversation_kind=group` 标记；见[微信接入说明](wechat-db-setup.md)。邮箱配置见[邮箱接入说明](email-setup.md)。

## 启动

Windows、PowerShell 7.2+、Go 1.26+、Node.js 24 和 GCC 为当前开发环境要求。在项目根目录运行：

```powershell
.\scripts\start-inbox.ps1
```

首次启动会生成数据库密钥，以当前 Windows 用户的 DPAPI 加密保存（默认配置路径 `data/private/inbox-key.dpapi`）；数据库默认位于 `data/messages.db`。数据库与原有密钥之后复用，不重新加密覆盖消息。另有独立的稳定服务凭据，由 CurrentUser DPAPI 保存于 Windows LocalAppData Known Folder 下的 `SocialIntelligenceOS\credentials\service-v1.dpapi`，供后台启动器和 MCP 共用。默认启动**不复制剪贴板、不打印令牌**；数据库及密钥/凭据文件均排除上传，位置与保护边界见 [MCP 接入说明](<mcp-setup.md>)。

首次升级请先正常停止旧后台，更新代码/构建再启动；不接管正在运行的实例。首次或再次授权浏览器时，将上面的启动命令改为 `.\scripts\start-inbox.ps1 -CopyApiToken`，只有该显式开关才复制当前服务令牌；剪贴板管理器可能保留它，勿发给模型或他人。日常重启仍用普通启动命令，不需再次复制。

另开终端启动前端：

```powershell
cd apps/desktop
npm ci
npm run dev
```

打开 `http://127.0.0.1:1420`，在设置中粘贴本产品主令牌、确认默认勾选的记住设备选项并连接，再进入“消息”。记住设备需要后台加密存储，以及浏览器支持 IndexedDB 和 WebCrypto P-256；授权默认有效 **90 天**，不是永久免密。

浏览器保存不可导出的设备私钥，而非主令牌；刷新、关闭重开或同来源新标签页可自动证明设备身份，取得短时内存凭据并 GET 系统状态。短凭据更新不重挂业务页面。正常后台重启复用原服务凭据，不要求重新复制；暂时离线/503 保留设备授权，恢复后可继续。主令牌和短 bearer 均不写 localStorage、sessionStorage、URL 或日志，旧版 sessionStorage 主令牌会在启动时清除，不自动转为长期授权。

不勾选记住设备、旧后台或安全存储受限时，只连接**当前页面内存**，明确提示未长期记住；刷新后重新输入。忘记设备先清除本地并尽力撤销服务端，其他同源标签页会收到失效通知；离线时只确认本地已忘记，远端撤销未确认。授权到期、主动撤销、主令牌/实际监听地址改变或站点数据被清理后需重新配对；localhost 与 127.0.0.1 属于不同前端来源，不共享私钥。

恢复连接不会自动重放导入、同步或分析。变更操作因旧凭据返回 401 时，只刷新身份并提示用户核对后主动重试；不盲目再次提交。浏览器目前使用默认服务 `http://127.0.0.1:17890`，只对规范 127.0.0.1 监听开放设备授权，不新增任意后台地址输入。MCP 可直接读取同一受保护服务凭据，普通客户端 JSON 不再内嵌 token，详见 [MCP 接入](<mcp-setup.md>)。

需要撤销全部或清理未知残留授权时，先正常停止后台，再显式运行 `.\scripts\start-inbox.ps1 -RotateApiToken`；端口仍占用、原密文无效或存在任何显式 env token 都拒绝轮换，不自动停进程。之后浏览器重新配对、MCP 重启；若要同时复制新令牌用于配对，可再加 `-CopyApiToken`。每个工作区最多 32 项设备授权，无设备列表界面；仅删除浏览器站点数据不保证远端 grant 被撤销。完整边界见 [ADR 0013](<adr/0013-persistent-local-connections.md>) 与 [验证清单](<acceptance/T08-persistent-device-validation.md>)。

密钥文件只能由同一 Windows 用户解密；不要删除或移走它。仅复制数据库到另一台电脑不能恢复记录，跨设备加密备份与恢复尚待 T24 完成。脚本适用于当前开发阶段，后台服务安装尚未实现。

也可通过 `.env.example` 中的 `SOCIALD_DATABASE_PATH` 与 `SOCIALD_DATABASE_KEY` 在终端手动配置：本机固定磁盘绝对路径、32 字节随机密钥的 64 位十六进制字符串，两个变量必须一起设置；数据库路径拒绝链接、junction 和网络盘。密钥与本产品 API 令牌分开保管。

## 导入与管理

1. 点击“导入消息”，选择平台与本人账号，并选择 JSON 文件。
2. 点击“检查文件与来源”，核对平台、本人账号与条数，再确认导入。
3. 在“全部平台”中统一查看，也可以按平台、未读、置顶或归档筛选。
4. 搜索联系人、账号、对方 ID 或消息正文。选择会话查看历史，使用“标为已读”“置顶”“归档”等管理按钮。
5. 管理操作只改变本地状态，不改变原平台未读状态，也不向联系人发送消息。打开会话本身不会自动标已读。

每次最多 8 MiB、1000 条记录；正文最多 16000 UTF-8 字节；标识和名称最多 128 个字符。正文时间必须是包含时区的 RFC3339 时间。支持中文短词的字面子串搜索，目前不使用 FTS5 做搜索排序，FTS5 建表和索引触发器已验证。

同一平台、本人账号、对方 ID 和原消息 ID 相同且内容一致时计为重复；相同 ID 内容不同则整批回滚，不覆盖原记录。导入失败不会部分保存。分页绑定当前数据版本，导入或管理后会刷新列表；旧游标失效时重新读取第一页。

## 通用 JSON

可以上传下面完整对象，也可只上传 `messages` 数组，并在界面填写平台和本人账号。以下均为**合成格式示例**，不会自动进入产品。

```json
{
  "platform": "qq",
  "account_id": "synthetic-self",
  "account_name": "合成格式示例",
  "messages": [
    {
      "external_id": "source-message-1",
      "peer_id": "synthetic-peer",
      "peer_name": "合成联系人",
      "direction": "incoming",
      "body": "这是一条格式示例。",
      "occurred_at": "2026-11-12T08:00:00+08:00"
    }
  ]
}
```

`platform` 只能取 `qq`、`weixin`、`telegram`、`shanliao`、`email`；`direction` 只能取 `incoming`、`outgoing`。标识必须来自用户已有记录，不以昵称猜测身份。QQ、微信、闪聊的不同导出工具格式尚未逐个适配，需先转换为上述格式。

消息可以带可选 `read` 布尔值和 `conversation_kind`（`private` 或 `group`，默认 `private`）；邮箱消息还可带 `email` 对象（`subject`、`from_name`、`from_address`、`to` 字符串数组、`folder`）。群聊导入必须使用稳定的群会话 ID，不能仅凭昵称猜测群身份。界面会校验并保留这些字段，不将邮箱元数据丢弃。标准 JSON 导入的保存来源为 import，不能以此声称完成 IMAP 在线同步。

## Telegram Desktop 导出

支持 Telegram Desktop 导出的**单个个人私聊 JSON**（`type: personal_chat`）。在界面选择 Telegram Desktop 格式，填写本人数字账号 ID，不能用用户名代替；来源、方向以导出中的稳定 ID 与显式填写的本人 ID 校验。

字符串和可见文字片段会转换为纯文本；服务消息、附件、多媒体和无法确认发送者的记录跳过，并在结果中显示数量。不会读取附件路径或提取实体中的隐藏身份。全账号导出、群聊暂不支持，不能用导入声明实时连接。

[Telegram 官方导出说明](https://telegram.org/blog/export-and-more)；转换依据见 [官方 JSON 序列化源码](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/output/export_output_json.cpp)。

## 在线接入状态

- QQ：已有 OneBot 只读身份核验；持续收件尚待真实服务地址与 T06，核验不表示消息已连接。
- 微信：本机私聊和群聊文本可手动读取或明确开启后台周期读取；手动读取可用正文关键词筛选最近记录窗口，默认关闭，页面退出不停止已启用的后台，需电脑和后台保持运行；群聊只保留群会话 ID 和文本消息，不提供成员目录、@ 提及解析或发送；最近记录窗口不是完整历史/离线补漏。
- Telegram：管理导入记录，未开启实时接收。
- 闪聊：具体产品/接口尚待确认，仅提供统一格式导入。
- 邮箱：配置本机 IMAP 授权码后手动同步最近一批，尚未开启常驻收件；详见[邮箱说明](email-setup.md)。
- 发送、模型回复、审批、平台历史补齐均未启用。

本轮工程和界面验证使用合成数据。团队实名代码审查、真实账号授权与独立验收仍需完成。

## AI分类与联系人专属文档

工作台联系人目录及聊天页的个人档案可编辑公开姓名、公司、职业和私密备注，筛选好友/家人/同事/客户/合作伙伴等分类，查看候选来源并确认或拒绝。自动整理与公开搜索需分别明确授权；切页不取消已接受的后台任务。配置、最小公开查询范围和Markdown导出见[档案说明](ai-profiles-setup.md)。公开同名匹配不等于身份确认，不自动合并联系人。
