## 2. 安全前置与停测条件

1. 默认只用合成联系人、消息、临时加密库、协议端和模型 stub。工程验证可复用依赖缓存，但不得复用真实库、密钥、设备凭据、微信账号目录或 Telegram Session。
2. 不输出令牌/密钥、认证头、原始账号配置和真实聊天；证据只记脱敏错误码、假数据、版本、时间、请求类别和计数。真实数据测试另行约定最小范围及证据脱敏方式。
3. 当前授权覆盖离线工程检查及合成验证，不覆盖新登录、真实平台请求、付费模型/搜索、启用后台名单/日报/外发计划、真实发送或删除/迁移现有库。需要这些步骤时先由 kirinbao 明确授权。
4. 现有来源的“只读”只描述读取平台，不意味着已存在的自动整理/模型计划一定不外发。开始真实导入前，先核对并停用不打算测试的模型/计划授权；**本轮未代为更改现有配置**。
5. 真实发送只能在核对固定本人收件人、完整冻结正文、身份/版本、独立发送同意后单项执行。QQ/通用发送和微信暂停项不测试“发送成功”。
6. 出现跨联系人/工作区数据、未同意的模型请求/写操作/外发、凭据泄漏、unknown 被重试或破坏现有数据，立即停止该路径、保存脱敏证据并登记 P0/P1；不以连续点击或刷新“试通”。
7. `GET /health/live` 为 200、`GET /health/ready` 为 503 是当前预期：后者指通用无人值守链路未就绪，不能据此认定本地收件箱不可用，也不能伪造 ready=200。
8. 使用候选版本前先核对实际源码/构建/进程版本。旧浏览器批次和当前运行实例不能证明新候选；本轮不新开替代业务服务器、不覆盖现有 `dist`、不重启现有后台。

## 5. 100 条固定评测集与尚未满足的门槛

本清单**不是** 100 条评测消息。尚需制作并经指定人员审阅：50 条高风险、30 条已授权低风险、20 条其他/注入/信息不足；每条必须有合成/脱敏文本、意图、期望动作、允许的联系人证据、禁止数据、是否须确认、unknown/拒绝预期和理由。至少覆盖同名联系人、跨群/私聊、重复/编辑、撤权、超时和旧授权。

通用自动回复/审批/发送未实现的预期可以是“拒绝/未实现/不得发送”，不能给这类样例填“已成功自动回复”。相关能力以后实现再扩展执行层，保留旧版本与变更理由。原有 T10 Recall@5 等整项指标、T23 性能、安全/故障报告、T24 恢复、T25 原生交付和 T26 稳定性均保留，不以本轮准备勾销。
