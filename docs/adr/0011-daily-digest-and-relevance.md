# ADR 0011：每日消息整理与高相关提醒

日期：2026-11-16（Asia/Shanghai）  
关联：`CHG-T20-002` / `CHG-T21-002` / `FEAT-T20` / `FEAT-T21`  
状态：设计与任务拆分进行中，实际完成日期—。

## 决策

首版采用每天一次的持久化摘要计划，默认时间为上海时区 08:00，用户可以在设置中启停和修改时间。提醒先显示在工作台，不通过微信、QQ 或邮件主动发送。

后台每分钟检查一次计划，到点后以“工作区 + 日期”幂等生成一份摘要；重复启动、页面关闭或服务重启不会重复生成同一时段报告。用户可以手动立即生成，手动生成也使用相同的日期/水位和状态记录。

摘要范围为已经入库的消息。首版按会话分别限域，再聚合结果：未读、问句、@提示、金额、时间、承诺、待办和近期高频联系人优先进入候选。AI 每次只接收单个会话的有界消息和证据 ID，输出摘要、提醒优先级和引用；后端再合并成日报，禁止把不同联系人上下文直接混在同一个模型输入里。

提醒状态只表示建议：重要安排、金额、时间承诺、情绪冲突、未完成事项和模型不确定性进入“需要确认”；不触发自动发送。报告保留消息 ID、会话、来源平台、生成时间、处理水位和失败/unknown 状态。

## 群聊边界

当前 `conversations` 已有 `conversation_kind`，微信本地读取器支持明确选定的私聊和群聊文本；群成员、@提及和成员权限表仍未建模。因此日报可以覆盖已入库的私聊与群聊文本，但群聊提醒只依据会话消息和现有证据，不推断成员身份或群权限。后续仍需独立扩展成员/提及关系、群权限和平台事件归属，不能把私聊联系人档案逻辑直接套用到群聊。

## 数据与失败

- `digest_schedules` 保存启用状态、上海本地时间、时区、版本和最后成功日期。
- `digest_reports` 保存日期、状态、摘要、提醒、证据 ID、来源水位和错误代码；状态区分 queued、running、succeeded、failed、unknown。
- 模型未配置、额度不足、消息范围为空、服务重启和模型返回无效结果都必须可见；不显示“已完成”假回执。
- 电脑关机、休眠或后台停止时不执行；恢复后按日期幂等补跑，不承诺平台离线补收。

## 验收目标

1. 可设置每日 08:00 计划，启停和修改有版本冲突保护。
2. 同一天重复调度只生成一份报告；重启后可恢复 queued/running 状态。
3. 报告至少包含重要消息、提醒、来源会话、证据 ID、失败/unknown 和下一步。
4. 50 条合成私聊消息中，跨联系人证据泄漏为 0，未授权发送为 0，重复报告为 0。
5. 群聊明确显示“暂未接入”，不能伪装成已覆盖。
