# ADR 0008：微信后台受控读取

- 日期：2026-11-14（Asia/Shanghai）。
- 状态：设计采纳，实现/检查按FEAT-T05、FEAT-T06、FEAT-T08记录；不表示正式验收。
- 变更：CHG-T05-003 / CHG-T06-007 / CHG-T08-003。
- 后端/存储负责人angjustinl、指定审查joey；前端负责人joey、指定审查angjustinl；kirinbao组织真实验收。

## 背景

用户明确要求后台持续读取消息、聊天页展示结果。现有微信读取绑定单次HTTP请求和页面操作，关闭页面不能承担持续采集。账号初始化和后台启动已由用户运行，开发侧仅复核本地健康接口/首页HTTP200，未读取真实聊天。

## 决策

后台Go服务拥有轮询生命周期。默认关闭；用户读取会话列表后，明确选定最多20个私聊及10—300秒周期（默认30秒）再开启。产品SQLCipher库新增独立设置表，按本机工作区和微信账号保存开关、私聊标识与周期，不保存微信目录/数据库密钥。重启恢复同一账号已保存的明确授权设置。

POST `/api/v1/connections/wechat-db/monitor`提交完整设置。接口沿用Bearer、Host、Origin和工作区校验；启用核验固定账号和当前可读取的私聊，停止无需重新读取源。GET `/api/v1/connections/wechat-db/status`附带monitor缓存状态；页面状态轮询不打开微信数据库。

后台读取与手动读取共用单并发门闩，每私聊限时30秒。每个私聊验证账号、只读、会话和批量大小后独立原子入库，稳定消息ID去重；多私聊之间不承诺全局原子事务。聚合状态必须保留已提交结果，某个私聊失败不能声称其他已提交内容未保存。

修改/暂停先取消并等待旧工作器结束，再持久化/应用新设置。不能让HTTP请求取消连带取消已经确认开启的工作器；服务关闭时先取消等待工作器，再关闭产品库。暂停只针对后台轮询，手动读取仍需用户独立操作。

前端每5秒仅查缓存状态。新结果有新增消息时刷新消息中心；保持选中会话和AI编辑草稿，正在查看历史时提示新消息，避免强制跳回底部。离开页面只停止UI请求，不向后台发送暂停。服务版本尚旧时保留已有手动功能并提示更新重启。

## 限制

读取的仍是本机已同步、当前支持的私聊文本窗口，默认最近100、最大500条源记录；不包含群聊和媒体本体，不保证高消息量、电脑休眠、源库持续变化或后台退出期间无遗漏。limited及失败状态必须可见。

本子项只持久化配置，运行结果缓存于后台进程；没有可靠持续游标、通用持久任务队列、租约、死信或系统服务安装，T15/T19仍按原任务推进。电脑与后台必须运行，关闭浏览器可继续，关机后不会继续。

不开启自动发送或模型自动调用；路径、密钥、原始数据库错误不进入页面或日志。开发验证使用合成数据库/假连接器，不操作用户真实微信。

## 验证要求

加密设置默认/保存重开/账号隔离、v4迁移和取消；开启校验、鉴权/CORS、HTTP结束后持续执行、门闩串行、去重、暂停取消及关闭等待、重启恢复；客户端仅GET状态、开启/停止完整请求、旧服务兼容、错误/未知结果提示及阅读状态保留。指定人员正式审查和真实私聊验收另记。
