# ADR 0014：原生 Agent 与逐次确认的业务工具

日期：2026-11-17（Asia/Shanghai）
关联：`CHG-T08-007` / `CHG-T11-004` / `CHG-T12-002` / `CHG-T13-004` / `CHG-T20-003` / `CHG-T21-003`
状态：实现、整合全检与后端 race 已通过；指定非作者审查及 kirinbao 真实验收待进行，实际完成日期 —。工程证据见 [验证记录](<../acceptance/T13-native-assistant-validation.md>)。

## 1. 目标与非目标

在既有消息管理工作台提供真正的模型工具调用助手。模型通过 Chat Completions 的 `tools` / `tool_calls` 选择后端提供的固定业务操作，后端执行后用对应 `tool_call_id` 续推；不以关键词路由、预设演示或普通 JSON 回答代替 Agent。

“所有 API 权限”限于**已经实现的本产品业务 API**，不等于任意 URL、主机命令、文件系统、SQL、DSH 工具或平台凭据权限。登录/设备授权/撤销及模型配置修改保留人工专用；空列表脚手架和 501 API 不伪装可执行。自动发送继续关闭；模型不能新增权限、改工具 schema 或绕过平台规则。

不部署、不替换正在运行的后端、不操作实际凭据/消息、不连接真实模型或平台。实现检查使用合成数据。进程内 Agent 不代替 T15 持久任务/租约/可靠发件箱，也不代表原生 Tauri 或真实账号验收通过。

## 2. 协议与模型隔离

- `agent.ToolProvider.ChatTools` 与原有 `Provider.Analyze` 独立，保留结构化分析链路。工具协议每轮恰好一个调用或最终回答，`tool_choice:auto`、`parallel_tool_calls:false`；严格匹配调用 ID、工具名和 JSON 参数。
- 工具清单逐 method/path 对照当前契约：原有 62 项 = 44 项可执行（42 项业务与 2 项 health）+ 5 项人工专用 + 13 项未实现；另有 5 项 Assistant 控制接口不递归开放，共 67 个 HTTP 方法。目录按可读、需确认、人工专用、未实现如实展示。QQ 仅使用 Milky 1.3，已取消的 OneBot 不再列为可调用工具；历史接入文档不代表当前能力。目录与契约一致不表示全部真实连接器已完成调用验收。
- 固定模型目标沿用已有 HTTPS/本机地址、DNS/TLS、无重定向约束。平台和模型密钥只由后端持有；不进入工具 schema、调用参数、会话、前端存储或模型的工具结果。业务错误只回固定安全代码，不转发任意上游错误文本。
- 服务端系统规则和工具 schema 固定。会话 ID 以外不接受客户端历史、system、tools、URL、Header 或任意参数覆盖。业务数据、聊天和网页内容均为不可信数据，不得改变权限。

## 3. 认证、模型数据同意与不可变操作确认

1. 每次调用先经现有 Host/Origin/Bearer/工作区认证；会话归属绑定稳定设备 ID（或本机主主体），不绑定会轮换的 15 分钟 bearer，不在会话/运行中保留 bearer。
2. 发起每轮前人工核对模型、地址、将发送的数据类别和费用，再勾选**本轮**模型数据同意。绑定 `model_config_id` 及 `model_config_revision`，不能沿用旧目标或 A→B→A 前的确认。仅 env 配置的合法模型 revision 为 0；它不是“未配置”。
3. 普通固定读取在本轮同意内执行；**所有 mutation** 及有核验外呼副作用的 Milky GET 停在 `awaiting_confirmation`。后端冻结标准化参数、method/path、主体、模型绑定和有效期。前端展示完整参数/副作用。
4. 确认只接受 action ID、当前模型绑定和新勾选的模型数据同意，不接受替换参数。原子消费一次；拒绝不调用业务或模型。暂停/恢复 AI 本身也需独立人工确认，不能由其他工具顺带解除暂停。
5. 每次模型调用和每次业务 dispatch 重验身份、模型和隐私边界；同进程调回原业务 handler，保留其确认、校验、幂等、权限和限域。递归 dispatch 前释放 Agent 状态锁和模型并发 gate；在业务路由取得 `aiMu.RLock` 后再次检查绑定，避免检查/执行间模型切换和写锁饥饿死锁。

## 4. 有界运行与失败恢复

- API：`GET /assistant/status`；`POST /assistant/runs`；`GET /assistant/runs/{run_id}`；`POST /assistant/runs/{run_id}/confirm`、`/reject`（均位于 `/api/v1`）。严格字段、重复键/大小写别名/未知键/null/类型/深度检查；16 KiB 请求上限，消息 1—8000 字符且仍受整体字节限制。
- 64 个会话、每会话 16 个运行、每会话同时最多一个执行中或待确认运行；历史最多 64 条/256 KiB，单次最多 6 次模型调用、12 次工具及 120 秒执行窗口；单工具结果 64 KiB、累计结果 256 KiB。不驱逐活跃/待确认运行来规避上限。
- 会话/运行仅进程内保存 30 分钟，待确认动作 5 分钟。资源不存在/不属于主体返回 404；已知过期 410；只有实际身份失效才返回 401。
- 状态为 `running`、`awaiting_confirmation`、`completed`、`failed`、`rejected`、`unknown`；202 不是成功。工具分别记录调用 ID、固定操作 ID、状态、HTTP 状态、有限数据或安全错误码。
- 初始 POST 在有界同步执行前分配 run ID；**若网络在客户端收到 run ID 前断开，客户端无法凭空 GET 找回**。不自动重发，必须人工核实业务结果。已知 run ID 可只读 GET 恢复；GET 不继续模型、消费确认或重放 mutation。
- 取消/断网/响应不可验证时不声称回滚；写入可能发生则记 `unknown`，只读刷新并人工核实。前端本地停止仅停止等待，不保证停止后端或撤回已执行操作。设备短令牌刷新沿用“只读至多一次重试、mutation 不自动重放”。

## 5. 暂停与来源追踪

Agent 不能读取或操作已暂停 AI 的会话，唯一例外是**另行人工确认**的 AI 模式更新。会话列表过滤已暂停项并保留原分页游标，可能出现空页；需要检查下一页而非断言没有会话。

每次工具返回收集来源会话及全局敏感标记；下一次向模型发历史前重查这些来源。全局/历史摘要可能含不显式列出的会话，因此任一会话暂停时阻止相关全局操作；档案链接检查两端。若来源新近暂停，清除敏感会话历史/来源引用并失败，不把旧内容继续发送模型。既有人类 REST 查看功能不因此锁死。无法撤回已经送达模型的数据；应在发起前核对范围。

## 6. 共享额度和日报同意

SQLCipher schema v13 新增无会话外键的 `ai_assistant_call_reservations`，只保留无内容尝试记录。与原分析/档案/日报 reservation 在同一事务合计，按 Asia/Shanghai 自然日共享上限，默认 50、模型设置允许 1—1000。每次模型尝试先占额度，包括失败；重启不清零。共享容量 1 的模型 gate，避免并行工具与业务分析绕过限额。

日报立即运行要求显式 `confirmed:true` 和当前目标 ID/revision；每天运行计划的同意独立，明确覆盖每日对未暂停已入库文本的重复外发及费用。启用计划需目标绑定；关闭不要求模型可用。计划使用自己的 CAS revision（最小 1），不能与允许 0 的模型 revision 混淆。

迁移禁用旧版无目标绑定计划。**每次保存模型配置**在同一事务撤销周期同意并递增计划 CAS，需用户重新确认。日报仅选过去 24 小时未暂停内容、最多 500 条/每会话 20 条、有界整条消息裁剪至 32000 字节，保持时间顺序与会话证据限域。一次只分析一个会话，不跨联系人混输。

一天只持久化一份报告，`running/succeeded/failed/unknown` 均占当日记录，不以 force/upsert 重发模型；失败需显示并等下一日，不把不确定当重试许可。模型开始前后的暂停检查、输出/证据校验、provider 鉴权错误 503、失败/取消/超时状态如实记录。报告查询和手动结果统一 `{report,sending_enabled:false}`。详见 [日报决策补充](<0011-daily-digest-and-relevance.md>)。

## 7. 界面与交付边界

工作台使用白底、灰字、细分隔与紧凑导航，无渐变/光晕/装饰统计。保留既有业务入口、内存 AI 草稿和持久设备身份；页面 key 使用稳定会话句柄而非短 bearer。助手展示目标/额度、真实工具结果、待确认参数和明确 unknown，不把“模型回复”当作业务成功回执。

官方 modern-web-guidance 按固定提交项目级手工安装；没有安装上游缺失的 CLI，也没有修改 DSH 全局插件。来源见 [PROVENANCE](<../../.agents/skills/modern-web-guidance/PROVENANCE.md>)。产品事实见 [PRODUCT](<../../PRODUCT.md>)，实际界面规范见 [DESIGN](<../../DESIGN.md>) 与[设计扩展](<../../.impeccable/design.json>)；最终全检/race与隔离Chromium唯一确认轮（23条检查记录、5张截图）通过，首轮fixture失败及验证边界见[工程记录](<../acceptance/T13-native-assistant-validation.md>)。不以设计或辅助代理检查替代 joey/angjustinl 指定交叉审查和 kirinbao 验收。
