用户要求在界面配置AI模型，导入后分析全部记录，使用已授权的昵称、平台ID和聊天内容归入对应个人档案，并支持聊天合并。

## 模型配置

本机鉴权接口保存模型地址、模型、每日额度及API Key到产品SQLCipher库。密钥仅在页面内存中提交到本机后台，成功后清空；GET只返回是否已配置，不回显密钥，不保存到浏览器存储。沿用模型端点公网HTTPS/明确本地服务的传输校验，不把地址或密钥开放给模型。修改模型目标使旧自动授权指纹失效，需要重新确认。

## 全历史分批

导入确认页独立勾选AI整理，展示当前目标模型和数据范围。导入事务同时记录本次涉及会话的授权及持久作业，不依赖页面逐个排队；未授权导入只保存消息。按平台/本人账号/联系人ID建立唯一身份，昵称用于辅助理解，不用于数据库归属。

后台按消息本地序号升序，每批不超过20条和约20KB JSON；只在证据校验、租约和设置版本通过后推进实际处理水位。失败、取消和重启不跳过未完成批次，超长记录不能静默标为已分析。每日额度不足等待下一日。分批摘要和事实保留来源，不能把最后一批摘要当作整个历史。

AI读取当前授权会话的昵称、平台、联系人ID、人工提供资料和聊天正文；不接触凭据。公开资料搜索仍只使用明确公开姓名/公司，不发送聊天和私人备注。输出分类为建议，新事实仍待核实。

## 聊天合并

采用可撤销的档案关联：展示同名等候选，由用户确认两段会话属于同一人。保留各平台原消息、账号、来源和证据，不移动或重写聊天ID；联合文档按已确认关联汇总，AI权限仍按原会话独立配置。解除关联后恢复分开查看。同名本身不作为身份确认。

## 验证与边界

只使用合成模型、账号和SQLCipher临时库。覆盖配置不回显/重开、并发改模型、100条分批及重启、导入事务回滚、跨联系人证据拒绝、同名候选确认/解除和联合文档。真实模型费用、实际聊天效果、指定成员审查及真人页面验收单独登记。

工程交付与实际验证见[验收记录](../acceptance/T13-import-profile-validation.md)。全历史指产品当前已入库的文本记录逐批覆盖，不表示平台源数据全部获取、原附件已识别或长历史信息无损压缩。
