# ADR 0002：先定义事件流，持久化完成后再启用

- 日期：2026-11-12
- 关联：FEAT-T04 / CHG-T04-002
- 状态：接口预留已实现，实时传输与持久化未实现。

## 当前行为

`GET /api/v1/events` 先执行与其他业务接口相同的 Host、Origin、令牌和工作区校验。认证成功后返回 JSON `501 NOT_IMPLEMENTED`。不返回 SSE 连接、心跳或虚构游标；未授权请求仍为 401。

## 后续契约

- 未来使用 `text/event-stream`；前端通过支持授权头的 fetch 流读取，令牌不能放在 URL。
- 事件仅含 ID、类型、发生时间、工作区、资源 ID 与资源版本；不发送聊天正文、令牌或模型上下文。
- 事件表示“资源可能变化”，前端仍通过鉴权 API 重新查询资源作为最终状态。
- 事件 ID 必须来自持久化事件记录，不以进程内计数器冒充可恢复的游标。资源更新与事件记录须事务性提交。
- 重连携带最后已确认的事件 ID；超出保留窗口时，应明确要求重新读取资源快照，不能静默宣称补齐全部事件。
- 在 T05/T06 的资源和持久化底座以及相关任务恢复完成后，再实现事件保留、去重、补取、心跳和连接配额，按 T08 联测。

`api/openapi.yaml` 中的 PlannedEvent 仅记录上述设计，实际响应只声明当前存在的 401/403/501；不把未来 200 响应误写成已有能力。
