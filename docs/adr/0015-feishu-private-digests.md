# ADR 0015：飞书自建应用机器人本人私聊早晚报

- 日期：2026-11-17（Asia/Shanghai）。
- 关联：`CHG-T12-003` / `CHG-T13-005` / `CHG-T16-001` / `CHG-T17-001` / `CHG-T20-004` / `CHG-T21-004`。
- 状态：已实现并通过本轮全检/race/桌面及窄屏合成检查；[实际验证记录](<../acceptance/T21-feishu-private-digests-validation.md>)为工程证据，不以本文代替指定审查或真实验收。后端待 joey 指定审查，前端待 angjustinl 指定审查，kirinbao 真实验收待进行；实际完成日期 —，MVP / 扩展完成统计保持 0 / 27、0 / 5。本机操作见[启用指南](<../feishu-setup.md>)。

## 1. 背景与范围

用户要求北京时间 08:00、20:00 获得与本人相关的摘要和待办。本轮在自有 Go 后台内增加一个**默认关闭、单一固定本人目标、纯文本、无自动重试**的有限发送通道；使用同一企业租户内的飞书自建应用机器人，不使用群 Webhook，也不把 Milky、微信、邮箱或普通消息发送一并打开。

既有[每日 24 小时摘要](<0011-daily-digest-and-relevance.md>)保留本地预览语义；既有 [Agent 逐次确认协议](<0014-native-assistant-and-confirmed-business-tools.md>)继续适用。本轮不等于通用 T15 持久任务、T16 审批、T17 多平台发件箱整体已完成，更不等于部署到既有运行实例。应用发布、本人归属、真实模型、飞书消息和手机通知须分别验收。

同租户本人限定首先是产品用途与明确授权边界：本地保存配置不访问飞书身份 API，不能技术性证明输入的 Open ID 属于本人。界面必须标明“归属尚未验证”，`recipient_ownership_verified:false`；由本人在开放平台和真实验收中核对。不允许把“配置齐全”包装成“身份已经验证”。

## 2. 固定时间、半开窗口与离线策略

- 时区固定 `Asia/Shanghai`，时点固定 `08:00` / `20:00`。窗口为 `[window_end−12h, window_end)`；08:00 覆盖前一日 20:00 至当日 08:00，20:00 覆盖当日 08:00 至 20:00。数据库保存 UTC 时间，界面明确北京时间。
- 手动预览只由服务器时钟推导最近完整窗口，不接受调用者窗口、日期、任意时间或 `force`；不会与滚动 24 小时报告混用。
- 启用计划从未来下一个时点生效。后台正常运行时仅允许 `FeishuScheduleGrace = 2min` 的启动宽限；忙而尚未占窗可在宽限内等待下一次检查。已占窗后不是重试队列。
- 服务启动先把遗留 `running` 收敛为 `unknown`，并跳过离线边界；休眠恢复、错过宽限亦只推进下次时点，不补发过去窗口。默认关闭，不用积压补跑或服务恢复触发意外消息。
- 手动发送仅在报告窗口结束后、下一固定时点前有效；过期不能发送旧报告。电脑必须开机、联网、未休眠且后台存活，不能承诺关机后运行。

## 3. 本地配置、绑定与同意

SQLCipher 的增量[迁移 0014](<../../migrations/0014_feishu.sql>)新增 `feishu_configs`、`feishu_schedules`、`feishu_reports`、`feishu_report_sources`、`feishu_deliveries` 和 `ai_feishu_call_reservations`，不改写旧日报或其他平台发送行为。

1. **凭据仅人工配置。** App ID、App Secret、本人 Open ID 通过已认证的本机专用表单保存；不新增飞书环境变量、用户令牌输入、任意出站 URL 或模型可改凭据工具。App Secret / 原始 Open ID 只持久化在本机加密库，前端敏感表单值不写浏览器持久存储，GET 不取回原值，状态目标脱敏。
2. **显式保留密钥。** `retain_secret:true` 仅允许同 App ID、当前已有密钥且本次提交空 Secret；空 Secret 不是隐式保留。每次保存仍须输入完整本人 Open ID。换 App ID 不能沿用旧 Secret。
3. **绑定不是单一显示名称。** `FeishuBinding` 同时冻结 `model_config_id`、`model_config_revision`、`config_revision`、`target_binding_id`；目标绑定来自 App ID 与接收 Open ID 的哈希，不向模型暴露原始接收标识。配置 CAS 和计划 CAS 各从 1 起，环境模型 revision 0 合法；未启用计划的空绑定 / `config_revision:0` 亦合法，但不能据此外呼。
4. **防 ABA 与旧授权复用。** 每次飞书配置保存/清除、每次模型配置保存（包括同值保存）在事务中撤销自动计划并增加计划 CAS。修改后切回相同值也不能恢复旧同意。CAS 冲突先读取，不自动重放 mutation。
5. **模型与飞书外发独立同意。** 手动生成只同意当前模型处理，手动发送另行核对冻结正文、窗口、目标及哈希。自动启用同时明确持续模型数据处理/费用与持续飞书发送；绑定当前模型/配置/目标及计划版本。关闭计划或清除配置不要求模型可用或有额度。

## 4. 选择、分析、待办和正文冻结

仅使用窗口内已经入库且未暂停 AI 的私聊/群聊文本。固定相关性启发式阈值至少 3，最多 500 条候选、4 个相关会话、每会话 20 条，并继续按模型输入预算裁剪；它不是保证找全重要事项的语义相关性服务，不补抓平台消息或上传附件正文。

按会话独立调用现有 `Analyze` 并校验证据归属，不把多联系人消息混进一次输入。本地聚合经校验的摘要。待办由后端从原文形成带 `evidence_ids` 的候选并标为 **“待人工核对”**（`needs_review:true`）；模型 `Draft` 仍是回复草稿，不能假扮提取任务。候选不会创建、承诺或执行真实任务。

分析、档案、旧日报、Agent、飞书共用上海自然日持久额度和容量 1 的模型 gate，默认每天 50 次，可设 1—1000。新 reservation 纳入同事务总额统计，每次会话模型尝试前占用，失败不返还，重启不清零；平台限频/月额度另算。至多 4 次会话分析不意味着只有 1 次额度，也不保证全部会话都能成功完成。

报告在生成成功时冻结：

- 窗口、触发方式、模型/配置/目标绑定与计划版本；
- 摘要、原文待办候选、有限证据摘录、**将实际发送的完整文本**；
- 所有进入模型的来源会话及 AI 设置 revision，而不只保存最终挑选的几条引用；
- `content_hash = SHA-256`，覆盖报告 ID、窗口、文本与完整 `FeishuBinding`；以及截断、错误和生成时间。

本机报告正文预算 8000 字节，连接器文本预算 12000 字节、出站请求预算 16384 字节。必须按 UTF-8 安全裁剪，并实际检查两层 JSON 编码后的字节数，不能用字符数替代。截断要有明确省略提示，完整冻结文本可在发送前核对。原始内容中的主动 `<at>` 标记失活，避免引入提及；输出中出现凭据或非法证据则拒绝，不临时改用未预览文本。

## 5. 完整来源追踪与暂停屏障

每次模型派发、结果落库、报告读取（latest / by ID）及发送前，重新检查当前模型/配置/目标绑定和**完整** `source_refs`。来源必须仍存在、未暂停且设置 revision 一致；删除、暂停→恢复或其他版本变化都不能让旧报告重新获得读取/外发资格。配置或模型换回旧值也不能复用旧正文。

派发使用后端隐私屏障，与配置/模型/来源设置修改协调。变更先取消尚可取消的任务，等待相应屏障后才确认；**确认返回后不得新开始相关模型或平台请求**。此保证不是撤回：变更前已经开始的外部请求可能仍有作用，已交给模型的数据、飞书已接受消息不能收回。

计划保存/停用在取得派发写屏障后再次取消任务，覆盖首次取消快照后才注册的领取者。计划报告在每一次模型额度预留/`Analyze` 之前及最终正文落库之前，持有读屏障复核当前 `enabled`、计划 `revision`、完整 `FeishuBinding` 和 `LastWindowEnd == report.WindowEnd`；停用后以相同绑定重新启用或同值重存亦不能复活旧任务。领取已推进 `NextWindowEnd`，因此不能将它误作当前报告授权条件。未启用计划不妨碍另行人工确认的手动生成，但停用操作会保守取消当前受管任务。

历史正文不可重读不等于销毁审计事实。状态可保留最新报告 ID 与最小投递元数据；独立投递 GET 可显示窗口、绑定、哈希、状态、错误码和平台消息 ID，供人工核实，不暴露旧正文或原始接收标识。已存在投递优先只读返回，不通过重新校验失败诱发另一份投递。

## 6. 持久占窗与无重试发送

本轮使用同一加密事实来源中的报告和投递账本，而非前端内存或定时器去重：

- 报告有 `UNIQUE(workspace_id, window_end)`；调用任何模型前先持久占窗。任意状态都占用同一窗口，不以失败、重启、换配置、换目标或 force 再生成。
- 投递亦有 `UNIQUE(workspace_id, window_end)` 及报告唯一约束；**获取令牌/发送 HTTP 之前先提交 running 投递**。幂等键不含配置或目标维度，不能换目标绕过。
- 只允许服务器持久报告的匹配 `content_hash`、当前绑定和未过期授权进入发送器。模型/调用者不能提交任意文本、收件人、URL、Header 或新的 UUID。
- 飞书 `uuid` 使用该持久窗口投递身份，最长 50 字符；官方仅保证 1 小时去重。永久不重发依赖本机账本，不依赖平台缓存，也不宣称跨本机与平台事务的 exactly-once。
- 只读 GET 不领取任务、不继续模型、不消费确认、不重放发送。POST 一旦占用可返回 HTTP 202 `running`；报告的 `delivery` 字段允许在发送响应丢失后恢复查询。未拿到 ID 时先读状态/最新报告，不重发 POST。
- 工作由后台生命周期管理，有界执行、取消和关闭等待；不是脱离持久状态的无限 goroutine，也不是可自动恢复/重试的通用任务租约。

报告/投递状态统一为 `running`、`succeeded`、`failed`、`unknown`。重启遗留 `running→unknown`；消息提交后断网、超时、5xx、响应丢失、无法校验 JSON 或缺少明确成功字段进入 `unknown`；`230049` 亦作为发送中/结果未知，而非成功。获取令牌失败尚未提交消息，可记录已知失败，但同窗仍不自动重试。

只有 **HTTP 2xx + 显式存在的 `code=0` + 非空 `data.message_id`** 才算飞书平台接受。`succeeded` 不代表手机系统通知或用户已读。明确拒绝进入 `failed`，含义不是“可重发”；频率、月额度、权限和身份错误均无自动 token-refresh-and-replay、退避重试或换目标补发。认证/权限/接收目标不可用时只按同一授权绑定撤销自动计划，不能误撤销较新的人工授权。

## 7. 固定官方协议与安全传输

以[当前 tenant access token 文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token.md)和[发送接口文档](https://open.feishu.cn/document/server-docs/im-v1/message/create.md)为依据：

1. 固定 `POST https://accounts.feishu.cn/oauth/v3/token`，`application/x-www-form-urlencoded`，四字段 `grant_type=client_credentials`、`client_id`、`client_secret`、`scope=im:message:send_as_bot`。读取当前响应的 `access_token` / `expires_in`，验证明确成功、Bearer 类型及最小发送 scope；不混用历史 internal token 的字段/缓存语义，不自动降级到旧接口。
2. 令牌按不透明 Bearer 处理。当前格式为 JWT，不检查旧 `t-` 前缀或固定长度；预留超过官方建议 4 KB 的空间，项目接收上限 16 KiB，响应总上限 64 KiB。只做后台内存单项缓存，按 App ID / Secret 区分并在过期前留余量；令牌不入库、不回前端、不进入模型/日志。失效可清缓存，不能据此自动重放本次消息。
3. 固定 `POST https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=open_id`，`Authorization: Bearer …`，正文仅 `receive_id`、`msg_type:"text"`、`content`、`uuid`。先 `json.Marshal({text:…})`，再将其作为 **字符串**放入外层 JSON，不手工拼接/转义。内容格式见[官方说明](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json.md)。
4. 生产端点不接受配置覆盖；无代理、无重定向、无自动重试，HTTP/1.1 且禁用连接复用以避免传输层重放，TLS 至少 1.2、单 HTTP 请求 20 秒超时。合成测试可注入 fake transport，不提供生产任意 endpoint 注入。
5. 请求/响应有界，严格处理重复键、缺少/null code、不合法 JSON、错误状态和无消息 ID，不把 Go 零值 `code=0` 误认为成功。错误仅返回固定安全分类，不携带上游原文、请求头或敏感输入。

[官方月额度公告](https://open.feishu.cn/document/platform-notices/platform-updates-/custom-app-api-call-limit.md)含时限性调整，当前额度须在本人应用控制台核对；429 可能是频率限制也可能涉及额度，不能一律当作短暂故障。手机通知和[已读查询](https://open.feishu.cn/document/server-docs/im-v1/message/read_users.md)是不同能力，本版不新增已读权限。

## 8. REST 与 Agent 的最小权限

基础路径 `/api/v1/feishu`，10 个 HTTP 方法：

- GET `/status`；PATCH / DELETE `/config`；
- GET / PATCH `/schedule`；POST `/preview`；
- GET `/reports/latest`；GET `/reports/{report_id}`；POST `/reports/{report_id}/send`；
- GET `/deliveries/{delivery_id}`。

沿用本机 Host / Origin / Bearer / 工作区认证。GET 状态只查本地，不触发飞书/模型外呼；配置 mutation 人工专用，递归 Agent dispatch 也拒绝。mutation JSON 使用严格字段、大小写、重复/null/深度/尾随检查；本机 JSON 上限 8192 字节（不同于飞书出站 16384 字节），不接受任意查询参数。

Agent 只增加 8 项非凭据业务操作。可读状态不意味着获得凭据；所有 mutation 使用既有不可变动作确认，固定标准化参数、method/path、主体、绑定和 5 分钟有效期，一次性消费，不允许确认时换参数。当前模型数据同意必须重验；发送或启用计划另外要求本项**飞书外发同意**，不能把继续模型处理的勾选当作真实发送许可。工具与人工界面最终调同一业务 handler，保留来源、暂停、版本、窗口、幂等和 outbox 检查。

## 9. 不采用的方案与代价

- **群 Webhook / 外部成员 / 任意接收人：** 超出本人私聊需求和授权，不作为降级路径。
- **复用旧 24 小时日报直接发送：** 时间窗、同意和永久去重身份不一致，容易重叠或意外外发；保留旧预览，新增独立固定窗口。
- **只用平台 UUID、前端禁用按钮或内存锁：** 无法覆盖 1 小时后、重启和配置变更；改用同一持久自然窗口唯一约束。
- **unknown 后自动重试：** 平台可能已接受；宁可漏发、人工核实，也不冒重复私信风险。明确失败同样不开放同窗再试。
- **模型 Draft 当待办、只追踪最后几条引用：** 前者语义错误，后者可能让已暂停来源残留在摘要中；使用原文证据候选和完整输入来源版本。
- **自动补齐离线窗口：** 恢复联网可能产生意料外的多条旧消息与费用；只从未来时点开始。

这些取舍牺牲自动恢复、同窗重算和“保证送达”，换取有界外发、可核实结果与保守去重。若本机数据库丢失或被人为回退/替换，不能继续宣称原账本的永久去重；恢复与备份策略不在本轮自动化承诺内。

## 10. 验证要求与未完成项

开发验证仅用合成消息/加密测试库、fake RoundTripper 或本机 `httptest`，不得读取真实 `.env` / 业务数据库 / 聊天 / 密钥，不登录飞书控制台，不调用真实飞书或模型。下列是必须核对的边界，不是本文宣称已经通过的测试成绩：

1. 新旧库迁移及独立 CAS；同值保存、换回旧值、retain_secret 误用均不能保留旧授权，关闭不依赖模型。
2. 08:00 / 20:00 半开边界、未来生效、启动/休眠跳过、2 分钟宽限、手动过期；新旧 digest 互不串发送。
3. 500 / 4 / 20 与字节边界、中文/emoji/转义文本、显式截断、主动提及失活、跨会话证据拒绝、Draft 不变待办。
4. 全部来源（含未出现在最终引用中的来源）在生成、读取、发送各阶段有效；暂停→恢复、删除、配置/模型 ABA 后不可读取旧正文或继续外发；最小回执仍可核对。
5. 并发双击、响应丢失、重启、跨配置/目标和超过平台 1 小时去重期，仍只占同一报告/投递，不自动重试；202 / running 不是成功。
6. token 新协议四字段、长 JWT、scope/有效期/缓存隔离、无代理/重定向/隐式重放；发送缺 code、无 ID、5xx、网络异常和 `230049` 均不误判成功；429 / 月额度区分。
7. 模型共享 gate / 持久额度，逐会话尝试先占用、失败不退还；Agent 配置 mutation 禁用，其余 Agent mutation 逐项确认，发送/启用需额外外发同意，确认过期/参数替换无业务调用。
8. kirinbao 另行授权真实账号/模型、机器人发布/权限/可用范围、本人目标、平台接受和手机通知验收；joey / angjustinl 指定非作者审查分别登记。合成通过、辅助代理意见或上传成功都不能替代这些项目，也不能自动将 T12/T13/T16/T17/T20/T21 整项标为完成。
