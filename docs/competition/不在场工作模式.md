# 「不在场」工作模式说明

> 关联任务：`CHG-T27-002`、`CHG-T06-013` / `FEAT-T27`
>
> 文档日期：2026-11-18（Asia/Shanghai）
>
> 当前参赛方向：**盯（持续监看）+ 跑（长时执行）**  
> 赛事资料来源：开赛会 PPT。赛事时间、提交入口和评审规则以主办方最新公告为准，不覆盖本项目原有排期。

## 1. 我们交付的“不在场”是什么

Social Intelligence OS 不把“不在场”描述成一句“AI 自动管理社交”。它有一个可以被观察的工作循环：

```text
用户授权范围 → 后台持续监看 → 识别联系人和消息 → 读取该联系人档案
        ↓                  ↓
    低风险任务继续跑       重要/不确定事项停下来
        ↓                  ↓
  分批整理、更新档案、生成摘要       生成待确认草稿和原因
        └──────────────→ 用户回来看到回执、证据、待办和暂停原因
```

首版明确选择“盯 + 跑”：

- **盯：** QQ Milky、微信本地库、邮箱和 Telegram 的已授权后台接收，以及已授权公开来源检查。窗口关闭时后台仍可继续，但电脑、后台服务和平台连接必须保持可用；真实离场验收分平台登记。
- **跑：** 对离场后自动收取且允许分析的消息做后台相关性筛选、整理和定时摘要。结果含来源、提醒及缺口；既有历史导入不计入离场链路。
- **等：** 作为治理结果出现，而不是本轮主方向。重要安排、敏感信息、模型不确定、来源不一致或任何发送动作都停在草稿/待确认，不自动发送。当前发送能力保持关闭。

### 1.1 运行条件

1. 连接器已经由用户授权并通过账号、来源和权限校验。
2. 后台服务已经启动；关闭 Tauri 工作台不等于关闭后台，关机、休眠或服务停止时不会继续执行。
3. 用户提前对会话和模型确认分析权限、设定摘要时间与渠道。开启收件不自动开启 AI 分析，未获授权的会话不送入模型。
4. 自动整理只使用当前会话的昵称、平台、稳定联系人 ID、人工备注和当前批聊天证据；公开补充只使用用户明确指定的公开姓名/公司等范围。
5. 模型额度、联系人暂停、模型切换、权限撤销和身份关联都由产品后端固定规则控制，模型不能修改这些边界。

## 2. 「判」：动作清单和刹车规则

| 触发 / 频率 | 后台动作 | 最坏后果 | 默认处理 | 能否撤回 / 处理方式 |
|---|---|---|---|---|
| 新消息到达或监看轮询 | 接收、去重、识别会话、写入统一消息中心 | 漏掉重要消息或重复入库 | 自动记录并标记来源；缺口显式提示 | 已入库记录可在产品内删除/重新整理；平台原消息不改 |
| 已授权会话取得新消息，或摘要任务到点 | 核对模型与会话范围，调度整理或摘要 | 模型读取未授权内容或漏掉重要消息 | 只分析明确授权的范围，原消息和证据可回查 | 暂停后不处理新批次，失败记录原因 |
| 自动整理作业被调度 | 每批最多20条、约20KB，生成滚动摘要和事实候选 | 摘要误判或把推测写成事实 | 只保存候选和当前批证据；事实须用户确认 | 删除候选、暂停作业、模型切换后旧授权失效 |
| 重要安排、金钱、敏感信息或意图不明 | 生成草稿、风险和待办，不发送 | AI 替用户作出关系或履约决定 | 进入待确认队列，并说明触发原因 | 用户确认前不执行；过期草稿不能继续提交 |
| 模型服务超时、返回无效 JSON或证据越界 | 标记失败/unknown，按规则有限重试 | 误以为任务已经完成 | 显示失败原因和下一次可重试时间，不伪造成功 | 用户刷新确认状态后再决定是否重试 |
| 模型目标或服务地址变化 | 取消旧模型的自动/公开资料授权并提升档案上下文版本 | A→B→A 时旧授权被意外复活 | 必须重新勾选和确认；原聊天、人工备注和历史结果保留 | 重新授权前仅保留消息管理和手动查看 |
| 同名、公开姓名或同平台 ID出现匹配 | 提供候选，不改变档案归属 | 错误合并两个真实的人 | 需要用户核实后建立可撤销关联 | 解除关联后原会话、证据和 AI 权限仍独立 |

这张表回答“哪些事它自己做，哪些必须问你”。“自动”只表示在已授权范围内推进可逆的本地工作，不表示模型可以扩大权限或代替用户承担重要决定。

## 3. 「名」：身份卡和责任边界

### 3.1 运行身份卡

| 项目 | 本项目约束 |
|---|---|
| 它用谁的账号 | 只使用用户主动连接并通过平台校验的个人账号/授权服务；不冒充平台官方机器人，不接管未授权好友 |
| 它能碰什么 | 当前工作区、当前联系人档案、已授权会话消息、用户指定公开来源；按会话和工作区隔离 |
| 它不能碰什么 | 平台凭据、数据库主密钥、隐藏身份、私人位置、未指定公开页面、跨联系人私聊和未经授权的批量发送 |
| 预算和上限 | 模型每日1—1000次可配置；自动整理每批20条/约20KB；单个联系人关联最多20个直接会话；超限等待、失败或停下来，不静默丢弃 |
| 谁负责判定 | 后端固定规则校验授权、租约、额度、来源和发送边界；模型只提出分类、摘要和候选 |
| 谁能改变边界 | 只有用户通过设置、联系人权限和确认操作改变；模型输出、聊天正文和公开网页中的指令都不能改权限 |
| 出错时谁看到 | 用户回来看到待办、失败、unknown、证据来源、处理进度和最后成功水位；日志保留脱敏操作记录 |
| 业务责任 | kirinbao负责产品范围、测试验收和最终交付；angjustinl负责后端/AI；joey负责前端/桌面/UI，非作者交叉审查 |

### 3.2 身份关联卡

平台、账号、联系人稳定 ID 是归属依据；昵称和姓名只是理解和候选线索。同名不等于同一人，跨平台相同 ID 也不自动等同。确认关联只生成联合查看文档，不移动消息、不复制权限、不把第三人的档案带入模型上下文。

## 4. 「证」：用户回来时看到的回执

回执不是“已为你处理完成”一句话，而是一屏可核对的结果：

| 回执区域 | 必须显示 |
|---|---|
| 发生了什么 | 平台、联系人、会话、触发时间、消息/公开来源范围 |
| 做了什么 | 接收、去重、整理第几批、生成候选、生成草稿、暂停或等待 |
| 做到哪一步 | `queued / running / completed / failed / unknown / paused`，以及已处理/总条数和最后成功序号 |
| 为什么这样做 | 使用的联系人档案、授权类型、模型目标、触发的风险规则 |
| 证据在哪里 | 消息 ID、当前批消息、候选引用、公开来源 URL；原始记录和联合文档分开展示 |
| 还缺什么 | 待确认事项、失败原因、额度恢复时间、下一步按钮和是否可重试 |
| 能不能撤回 | 删除候选、暂停作业、解除关联；外部平台已发生的操作必须显示真实回执或 `unknown`，不伪造可撤回 |

### 4.1 “假装做完了”反例

- 只收到模型 HTTP 200，未保存档案结果：显示 `failed` 或 `unknown`，不显示“已完成”。
- 任务显示“整理完成”，但已处理序号小于总条数：显示剩余批次数，不能把最后一批摘要当作全历史。
- QQ 账号刚刚核验成功但连接器已断线：显示“最近核验成功/当前未持续在线”，不能显示正在接收。
- 外部发送请求超时但没有平台回执：显示 `unknown` 并要求人工核对，禁止自动重发。

## 5. 五分钟可运行演示路径

演示使用已授权的实际测试账号。先跑微信私聊/群聊，再验证 QQ 授权私聊。此处是验收脚本，未登记通过。

1. **提前设置：** 选择会话、授权分析、设置演示时段的摘要和提醒；准备未授权会话作对照。
2. **离开：** 关闭工作台，保留后台服务和平台连接；记录离场时间。此后不上传文件、不打开网页、不点击同步。
3. **发送新消息：** 由测试联系人在原平台发带唯一标记的新私聊和群聊文本，其中一条与本人相关；未授权会话也发一条作对照。
4. **用户回来：** 检查自动收件时间与消息来源，对照原消息核验摘要和提醒；未授权会话没有新增或被送入模型。重要安排只提示，不自动发送。
5. **故障回执：** 在一轮中断开平台连接或重启后台，检查可恢复时能继续收件，无法补齐时明确提示缺口、最后成功时间及恢复条件。

至少连续运行三次，记录版本、离场与收件时间、消息证据、摘要/提醒回执及故障结果。预载或手动导入的消息只用于工程预演。详细通过标准见[无人值守收件任务说明](../无人值守收件任务说明.md)。

当前工作台已在个人档案页加入“不在场回执”卡：用户回来后可直接看到离场动作、任务状态、已处理/总条数、更新时间、失败原因、下一步和发送关闭边界，不需要从多个区域拼出“是否真的做完”。工程验证见 [T27 回执卡验证记录](../acceptance/T27-unattended-receipt-validation.md)。

## 6. 两周、500元的最小验证计划

**可证伪判断：** 对消息量较大的多平台个人用户，离线4小时后，按联系人分批整理和回执摘要能让用户首次查看消息的人工分拣时间减少至少50%，同时保持“未授权模型调用为0、重要事项误自动处理为0”。只要任一项不达标，就缩小范围或撤回自动整理，而不是继续堆功能。

- 第1—2天：邀请3名符合条件的测试用户，记录离线前未读量、联系人数量、人工整理耗时。
- 第3—9天：每人使用一周，至少覆盖一次页面关闭、后台恢复、模型超时、暂停、模型切换和同名候选；每天记录处理量、失败、人工返工和待确认项。
- 第10—12天：回放固定测试集，统计跨联系人泄漏、未经授权调用、进度水位跳跃、假完成和重复处理。
- 第13—14天：访谈并决定保留、缩小或撤回“离场自动收件与整理”的渠道范围。预算用于测试激励和必要的模型调用，真实支出按收据登记。

通过条件：人工分拣时间中位数下降≥50%；未授权模型调用0；重要事项自动发送0；失败/unknown可解释率100%；每位用户至少能从回执找到下一步。未通过则保留消息统一管理和手动草稿，关闭后台自动整理。
