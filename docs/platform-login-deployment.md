# 本机部署与平台登录指南

> 日期：2026-11-18 · 时区：Asia/Shanghai · 关联：FEAT-T04 / CHG-T04-008。
>
> 范围：Windows 本机的 QQ、飞书、微信、Telegram 登录或授权。此文是操作指南，不是平台已登录、功能已部署或真实账号验收通过的证明。

**已有运行实例的用户：先看第 0 节及对应平台章节，不要重复执行“全新部署”。** 本产品没有统一的四平台扫码登录页；“连接本地服务”“平台登录”“读取会话”“授权模型处理”“开启发送”是不同操作。

## 0. 先确认版本和当前能做什么

本指南依据本轮开始时已核对的工作台功能基线 `feat/mcp-service@7deabc1678c394830b6ecc96744d6e37744b5874`；本次只补文档，不升级后台或前端。Telegram 个人号另有实现版本，见第 6 节，不能据此认为当前工作台已有该能力。

| 平台 | 登录或授权发生在哪里 | 当前工作台的实际能力 |
|---|---|---|
| QQ | 独立的 Milky 1.3 协议端 | 核验本人账号与版本、选定好友私聊历史同步、授权名单后台接收；发送关闭 |
| 微信 | 官方 Windows 微信客户端；另配置本人本机加密聊天库 | 选定私聊或群聊文本的手动读取、授权名单周期只读；不是网页登录，不发送 |
| 飞书 | 飞书开放平台的企业自建应用机器人 | 给同租户的本人私聊发送另行授权的早晚报；不读取飞书聊天，不是个人号登录 |
| Telegram | 当前版本先在官方 Desktop 客户端登录；个人号扩展见第 6 节 | 当前版本只管理导入记录；个人号扩展不能直接在本实例使用 |

### 当前这台机器的特别说明

已有运行环境的代码和原有数据不在同一个根目录：

```text
代码工作树：D:\msg_manager\.runtime\main-push-20261116\repo
原有数据根：D:\msg_manager\data
Web：http://127.0.0.1:1420/
后台：http://127.0.0.1:17890/
```

当前启动方式复用了原有加密数据、数据库密钥和微信配置，详见[已有启动记录](<../技术文档.md#431-后续授权的本机启动2026-11-18-1918asiashanghai>)。**不要直接在代码工作树重新运行通用启动器或微信初始化脚本**：它们按脚本所在仓库定位数据，可能选到另一份配置或创建空库。不能仅靠设置数据库路径环境变量来改变通用启动器的数据根，也没有 `-DataRoot` 参数。

本机微信已有保存的受保护配置，先尝试第 4 节的页面读取；不要先重取密钥。本次整理文档不会登录任何账号、重启服务、迁移数据、轮换令牌或开启后台计划。

## 1. 凭据准备与安全规则

| 凭据 | 用途与输入位置 | 不能拿来替代什么 |
|---|---|---|
| 本产品服务令牌 | 工作台“设置”中连接本地后台 | 不是任何平台的登录密码、Milky AccessToken 或数据库密钥 |
| 本产品数据库密钥 | 由启动器加载 Windows DPAPI 保护记录 | 不是服务令牌；丢失后不能靠重新生成恢复旧库 |
| QQ Milky AccessToken | 后台启动进程的 Milky 配置 | 不是 QQ 密码，不是本产品服务令牌 |
| 微信聊天库密钥 | 本人主动初始化或隐藏输入，本机 DPAPI 保存 | 不是微信密码、服务令牌或本产品数据库密钥 |
| 飞书 App Secret / 本人 Open ID | 飞书早晚报的人工配置表单 | Open ID 不是手机号、群 ID、user_id 或其他应用的 Open ID |
| Telegram API Hash、验证码、2FA 密码、Session | 仅在含个人号实现的版本中按第 6 节本机操作 | 不是 Bot Token；不要交给 Agent 或复制到配置截图 |

- 所有真实密钥、验证码、原始 Open ID、Session 和聊天内容均不要发到助手对话、Git、终端录屏或公开截图中。
- 只连接有权处理的本人账号、会话和数据。平台登录不代表自动授权所有联系人、群聊、模型外发或发送。
- 读取、同步或导入后的新消息，仍可能被**此前已授权**的自动整理、日报或飞书计划处理。首次验证前先检查既有计划；“来源只读”不等于绝不模型外发或后续发送，新增平台接入本身不授予这些权限。
- 本指南要求后台只监听本机 `127.0.0.1`；不要为登录平台开放公网端口、关闭鉴权或添加任意代理转发。仅用于可信个人电脑，loopback HTTP 与 DPAPI 不能防止同一 Windows 用户下的恶意程序使用凭据，也不是完整的本机多用户隔离。
- [环境变量示例](<../.env.example>)只是字段说明，**不会自动加载**。需要进程环境配置时，在启动后台的同一个 PowerShell 终端设置；不要把密钥字面值写入命令历史。
- 默认数据库、受保护密钥和平台配置与当前 Windows 用户及数据根有关。不要删除旧目录、只复制数据库到另一台机器，或把 DPAPI 密文当作已验证的跨设备备份方案。

## 2. 全新部署与工作台连接

**本节只用于没有现有实例、且代码根与预期数据根一致的全新安装。已有本机环境按第 0 节维护，不执行下面的安装或启动命令。**

### 2.1 环境与版本

准备 Windows x64、PowerShell 7.2+ x64、Node.js 24、Go 1.26+ 及可在 PATH 找到的 GCC。GCC 用于 SQLCipher 的 CGO 构建；原生 Tauri 另需 Rust、MSVC/Windows SDK 和 WebView2，本指南使用 Web 工作台，不声称已完成原生安装包验收。

在实际 Git 仓库根目录核对版本，不能把外层工作目录或另一个工作树当作工程根：

```powershell
git branch --show-current
git rev-parse HEAD
git status --short
```

同时确认本机端口 1420 / 17890 没有其他实例监听；已有监听时先确定所属实例，不自动结束未知进程。新装所需代码、依赖及外部协议端分别记录固定版本；不要混用不同分支的前端、后台、Python worker 或会话配置。

### 2.2 启动后台

在已经确认的仓库根目录使用[当前启动器](<../scripts/start-inbox.ps1>)：

```powershell
.\scripts\start-inbox.ps1
```

它会创建或复用该部署的数据和 Windows 保护的密钥，复用稳定服务凭据，普通启动不打印令牌、不改剪贴板。已有数据库却缺少原密钥时应停止并恢复原密钥，不能新建密钥“修复”。

若是首次授权浏览器，在**尚未启动后台时**，将上面的命令改为下面这一条；两条命令二选一，不启动第二套后台：

```powershell
.\scripts\start-inbox.ps1 -CopyApiToken
```

显式复制后只把剪贴板内容粘贴到本地工作台的服务令牌输入框。剪贴板管理器可能保留历史；不要用 `-RotateApiToken` 获取现有令牌，也不要沿用旧版示例每次生成新令牌。

### 2.3 构建并启动 Web

仅全新安装时，在另一个终端、同一仓库根目录执行：

```powershell
Set-Location .\apps\desktop
npm ci
npm run build
npm run preview
```

前端使用锁定依赖，preview 固定监听本机 1420 并启用 strict port；安装依赖、构建会写入该代码目录，不能在他人正在使用的共享依赖或构建目录中执行。

打开 `http://127.0.0.1:1420/`，进入“设置”，使用服务令牌连接默认后台 `http://127.0.0.1:17890`。可信个人电脑可选择记住设备，授权默认 90 天；浏览器保存不可导出的设备私钥，而不是主令牌。`localhost` 与 `127.0.0.1` 不共享浏览器来源身份。

本地 `/health/live` 正常不等于平台已登录；`/health/ready` 仍可能按当前实现返回 `503 NOT_READY`，不能因此反复重装或重置数据库。详见[统一消息中心](<unified-inbox.md>)及[设备连接说明](<adr/0013-persistent-local-connections.md>)。

## 3. QQ：在独立 Milky 协议端登录

### 3.1 准备并登录协议端

1. 从 [Lagrange 官方实现仓库](https://github.com/LagrangeDev/Lagrange.Core)选择实现 **Milky 1.3** 的固定版本，按其文档部署独立协议进程。该外部实现采用 GPL-3.0；本产品不捆绑协议端，不承诺所有 QQ 客户端版本兼容或账号免风控。
2. 按协议端自身提示完成本人 QQ 登录及必要的扫码/账号验证。二维码由协议端提供，不在本工作台生成。仅登录官方 QQ 客户端不能代替这一步。
3. 将协议端 HTTP 服务限制为本机地址并启用 AccessToken。需要 `POST /api/{action}` 和正向 `GET /event` WebSocket；不使用公网 WebHook。QQ OneBot 已取消，不使用旧变量或旧入口。

### 3.2 将协议端连接信息给后台

以下仅适用于已完成数据根核对、准备重新启动的部署。**已运行的当前本机实例先按第 0 节确认维护方案，不直接照此启动。** 示例端口 3000 必须按协议端实际配置调整：

```powershell
$env:QQ_MILKY_URL = 'http://127.0.0.1:3000'
$env:QQ_MILKY_ACCOUNT_ID = Read-Host '本人 QQ 号'
$env:QQ_MILKY_HISTORY_LIMIT = '20'
$milkyToken = Read-Host 'Milky 协议端 AccessToken（不是本产品服务令牌）' -AsSecureString
$milkyPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($milkyToken)
try {
    $env:QQ_MILKY_ACCESS_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($milkyPointer)
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($milkyPointer)
    $milkyToken.Dispose()
}
```

这只设置当前启动终端的进程环境；不是跨重启的持久密钥仓库，也不要打印这些变量。按本部署既有启动方式正常停止旧后台、在这个终端启动一次，保持原数据库、密钥和服务凭据不变。网页目前不能填写这三项协议端配置。

### 3.3 在网页核验和读取

1. 进入 **设置 → QQ Milky 协议端（主线）→ 核验账号与版本**。这一步会真实访问协议端；确认账号是本人且版本为 1.3。
2. 填写本人明确选定的好友 QQ 号，点 **同步一页历史**，核对入库结果。每页最多 30 条，不是完整历史迁移。
3. 如需持续接收，单独明确选择最多 20 个好友，点 **开启后台接收**。重启后保存的名单等待重新核验，不能把核验通过等同于后台正在接收。

只覆盖好友私聊文本，不含群聊、媒体或发送；最近页补查不保证可靠水位与全部离线历史。完整参数、限制和排障见 [QQ Milky 接入说明](<qq-milky-setup.md>)。

## 4. 微信：官方客户端登录 + 本机聊天库只读

### 4.1 已有配置时优先复用

1. 在本机官方 Windows 微信客户端扫码登录本人账号。工作台不会替代微信登录，也不会因配置了目录就证明微信在线。
2. 进入 **消息** 页的微信读取面板，主动点击 **读取会话列表**。
3. 选择私聊或群聊，按名称或 ID 查找并选定一个会话；可选填写本次读取窗口的正文关键词。
4. 点击 **读取并保存消息**，再在消息列表用微信筛选或会话内检索核对结果。
5. 持续读取需另行 **加入后台读取 → 开启后台读取**，最多 20 个会话；默认不开启。

当前本机已有受保护配置，先走以上路径。读不到时先核对同一 Windows 用户、同一微信账号和数据根，不删除配置、不重复提取密钥。

### 4.2 全新部署、尚未配置时

读取器支持明确配置的微信 4.x 本地加密库。先在微信的存储空间/文件管理中找到本人账号的 `xwechat_files/<账号目录>/db_storage`，不要选整盘、其他账号目录或本产品数据库。账号标识使用原始 wxid，不是昵称；账号目录末尾的四位附加后缀不属于 wxid。

**自动初始化只支持精确版本 4.1.15.56**，不是任意 4.x。它需要 Python 3.13 x64、固定 Frida 依赖及本人同意临时挂钩指定微信进程；版本不匹配就停止，不尝试其他版本偏移。

确认全新部署的数据根正确、没有可复用配置后，才在该仓库根目录执行：

```powershell
.\scripts\prepare-wechat-init.ps1
.\scripts\initialize-wechat.ps1
```

按[初始化说明](<wechat-db-setup.md>)在本机填写目录和 wxid、选择正确进程，并输入 `INIT <wxid>` 确认；等脚本显示“准备就绪”后，再退出登录并重新登录**同一账号**，不要结束微信进程。成功验证后才 DPAPI 保存配置，不打印或明文保存密钥。已有配置报 `Configuration exists` 是保护，不添加 `-Replace` 绕过。

如果已经合法持有本人聊天库密钥，改用[隐藏输入配置脚本](<../scripts/configure-wechat.ps1>)，不要把密钥写进命令行。配置保存后，按本部署已确认的数据根和启动方式正常重启后台一次。任何 `WECHAT_DB_*` 环境配置都会整体优先于配置文件，残留的部分变量可能使有效配置未被采用。

只读 SQLite 方式不写聊天正文，但 WAL 协调可能涉及辅助共享内存文件；不导出整份明文库。每次读取最近源记录窗口，不保证全历史或离线补漏，不含媒体、发送、群成员目录、@ 归属或群管理。详见[微信本地库接入说明](<wechat-db-setup.md>)。

## 5. 飞书：自建应用机器人，不是个人聊天登录

### 5.1 飞书侧准备

1. 在[飞书开放平台](https://open.feishu.cn/)创建**企业自建应用**，启用机器人能力；本人账号与应用须属于同一租户。
2. 申请并按企业流程批准最小权限 `im:message:send_as_bot`，发布包含权限、机器人能力及本人可用范围的新版本。仅保存草稿或勾选权限不代表已生效。
3. 准备该应用的 App ID（`cli_…`）、App Secret，以及**该应用下本人的 Open ID**（`ou_…`）。
4. 可按[官方 Open ID 指引](https://open.feishu.cn/document/platform-overveiw/basic-concepts/user-identity-introduction/open-id.md)，在 API 调试台“发送消息 → receive_id_type=open_id → 快速复制 open_id”中选本应用和本人，仅复制标识，**不要点击真实发送**。
5. 在飞书中找到并打开该机器人会话，用于后续人工核对。已有会话不能替代应用权限和收件人归属核对。

不用群机器人 WebHook、用户 OAuth 回调、消息事件订阅或公网服务；也不需要为本产品申请读取消息或批量通讯录权限。

### 5.2 工作台保存配置与首次验证

1. 左侧进入 **飞书早晚报 → 人工配置自建应用与本人 Open ID**。
2. 本人在本地填写三项资料，核对应用、租户和本人目标，勾选保存同意，点 **保存本机配置**。
3. 保存仅写入本机加密库，不验证 Open ID 归属，不调用飞书或模型，也不发送消息。`configured:true` 不能作为账号、权限或手机通知已验证的证据。
4. 若另行愿意使用早晚报，先在设置中配置模型；在飞书页同意本次模型数据处理后，点 **生成最近完整窗口预览**。这会外发符合规则的已入库文本给模型并可能收费，不是登录必需步骤。
5. 人工核对完整冻结正文后，另行勾选本次飞书发送同意，再点 **发送这份预览至本人飞书**，在官方客户端核对。平台接受不等于已读或手机通知。

自动计划默认关闭。需要时另行同意持续模型处理及持续飞书发送，才启用北京时间 08:00 / 20:00 固定早晚报；保存飞书或模型配置会撤销旧计划授权。发送 `unknown` 或响应丢失时只读查回执并人工核实，不盲目重发。详见[飞书早晚报接入说明](<feishu-setup.md>)。

## 6. Telegram：先区分当前导入版与个人号扩展

### 6.1 当前运行版本：官方客户端登录后导入

当前 `feat/mcp-service` **没有 Telegram 个人号授权入口，也没有实时收件**。不能把手机号、Bot Token、API Hash 或验证码填入本产品服务令牌框。

1. 在官方 Telegram Desktop 客户端完成账号登录。
2. 打开有权处理的**单个个人私聊**，使用客户端“导出聊天记录”，选择机器可读 JSON。
3. 在工作台点 **导入消息**，选择 Telegram Desktop 格式，填写本人数字账号 ID，检查文件与来源，再确认导入。
4. 在 Telegram 平台筛选中核对文本和方向。应用 API ID、用户名、手机号或对话 ID 不能代替本人数字账号 ID。

本导入器不支持全账号导出或群聊；附件、服务消息等会跳过并显示数量。导入不表示账号已连接或后台开始实时接收。格式及[官方导出说明入口](<unified-inbox.md#telegram-desktop-导出>)见统一消息中心文档。

### 6.2 Telegram 个人号扩展：另一实现版本，未部署到当前实例

已只读核对远端分支 `feat/telegram-personal` 的既有提交 `4f8ee7d93926f251aeb1aff1b7647f64b4317bda`。该版本有个人账号实现，详见[固定版本的 Telegram 专用指南](https://github.com/qilinbro/msg-manager/blob/4f8ee7d93926f251aeb1aff1b7647f64b4317bda/docs/telegram-setup.md)。**分支已推送不等于已合入当前工作台或部署完成。**

部署前需核对整套前后端、Python worker、加密数据库版本与数据根，另行确认停机/切换或使用隔离测试环境。不能只复制单个前端文件、脚本或 worker，也不能让未核对兼容性的分支直接打开现有加密库。本次不切换现有实例。

以下步骤**只适用于已经明确部署该完整实现的环境，当前运行目录不适用**：

1. **申请本人的应用凭据。** 用本人 Telegram 账号登录 [my.telegram.org](https://my.telegram.org)，进入 **API development tools**，按[官方申请说明](https://core.telegram.org/api/obtaining_api_id)取得自己的 API ID / API Hash。不使用网上共享凭据、BotFather Token 或导出的 Desktop 会话代替。
2. **准备隔离依赖。** 需要 Python 3.10+ x64。该版本的[依赖声明](https://github.com/qilinbro/msg-manager/blob/4f8ee7d93926f251aeb1aff1b7647f64b4317bda/scripts/telegram_user/requirements.txt)锁定 `Telethon==1.45.0` 与 `python-socks[asyncio]==2.8.1`。准备脚本创建独立 Telegram 虚拟环境，不修改微信初始化环境；无法找到解释器时，使用准备脚本的 `-PythonPath` 参数指定本机绝对路径。
3. **本机交互登录。** 在该版本、已核对数据根的仓库根目录，先运行[准备脚本](https://github.com/qilinbro/msg-manager/blob/4f8ee7d93926f251aeb1aff1b7647f64b4317bda/scripts/prepare-telegram.ps1)，再运行[初始化向导](https://github.com/qilinbro/msg-manager/blob/4f8ee7d93926f251aeb1aff1b7647f64b4317bda/scripts/initialize-telegram.ps1)：

   ```powershell
   .\scripts\prepare-telegram.ps1
   .\scripts\initialize-telegram.ps1
   ```

4. 按实际向导顺序输入：**API ID → API Hash → 可选本地 SOCKS5 代理端口 → 带国家代码的本人手机号 → Telegram 登录验证码 → 可选二步验证密码**。代理端口留空为直连；只填写本人已经运行的本地代理端口，不修改本产品 API 监听地址。连不上时检查自己的网络，不循环申请验证码。
5. API Hash、手机号、验证码和二步验证密码隐藏输入；**没有二维码登录，也不支持 Bot 账号**。验证码可能发到已登录设备，具体由 Telegram 决定，不承诺短信送达或绕过二步验证。
6. 核对终端显示的本人账号及数字 ID，确认后输入 `SAVE` 才保存。使用内存 StringSession，不创建明文 SQLite Session；API ID、API Hash、Session、预期账号及可选代理端口以 CurrentUser DPAPI 保护。保存位置按该实现的工程根计算，不会自动迁移第 0 节的旧数据根：

   ```text
   data/private/telegram-user.dpapi
   ```

7. 打开 **设置 → Telegram 个人账号**，核验本人账号、加载最近会话，明确勾选 **1–10 个个人私聊**，设置 **30–900 秒**读取周期（默认 60 秒），再开启后台收件。状态页读缓存，不会因为打开页面就登录或读取平台。

新选私聊先建立最新消息基线，随后按消息 ID 分批增量读取，**不回填基线之前的历史**；同账号重启可继续既有水位。会话列表只是有界最近窗口，不是通讯录全量；不全局按手机号或用户名搜索。只读私聊文本，不读群组、频道、秘密聊天，不下载媒体、不自动标已读、不发送。已另行授权的联系人自动整理或日报仍可能处理新入库消息；本次平台登录不授予模型权限。

**Session 具有账号授权能力，不是 Telegram 签发的只读 Token。** 只读是本产品开放接口的限制，同一 Windows 用户下的其他程序仍可能解密 DPAPI。需要撤销时，到官方 Telegram **设置 → 设备**结束对应会话；删除或替换本地配置不等于服务端撤权。已有配置默认拒绝覆盖，确需重新登录时先暂停连接器并人工确认 `-Replace`；保存失败或取消后，也应到官方设备页核实没有遗留会话。

登录过期、账号不一致或限流时先按专用指南处理；限流等待不因暂停、重新启用或重启而缩短。初始化成功、账号核验、后台开启、首次实际收件是四个独立结果，真实账号验收仍待本人进行。

## 7. 首次验证与常见问题

| 现象 | 应检查什么 |
|---|---|
| 工作台连接本地后台返回 401 | 使用本产品服务令牌，不使用平台令牌；核对当前实例、服务地址和浏览器来源；不要先轮换凭据 |
| `/health/ready` 返回 503 | 当前完整无人值守链路尚未完成；与某个平台已登录、存储是否可用分别核对 |
| QQ 已在官方客户端登录，但核验失败 | Milky 协议进程是否运行、版本是否 1.3、URL/AccessToken/本人 QQ 是否匹配 |
| 微信已登录但未配置、读取失败或列表不对 | 当前 Windows 用户、原数据根、wxid、聊天库目录、原密钥和残留 `WECHAT_DB_*`；不要删除旧配置 |
| 飞书显示已保存但没有消息 | 保存不是发送或联网验权；核对已发布权限、本人可用范围、同应用 Open ID、报告和独立发送回执 |
| 找不到 Telegram 登录按钮 | 当前版本本来没有；先用 Desktop 导入，或另行准备含个人号实现的完整版本，不能只换网页资源 |
| 同步、生成或发送结果不确定 | 先读取既有状态、回执并人工核对；不要自动重复提交，尤其不能对 unknown 盲目重发 |

首次验收要分别记录代码版本、正确账号、选定会话、读取结果和平台实际回执；只保留脱敏证据。模拟测试、页面显示“已配置”或健康检查成功不能替代真实账号验收。本指南没有替任何平台完成这类验收。

## 8. 启停、撤权与维护

- 电脑、网络及独立 Go 后台需要保持运行；关网页不等于停后台，休眠或关机不能保证接收或计划执行。当前没有自动安装 Windows 服务或开机启动。
- QQ **停止后台接收**只停本产品的接收授权，不等于退出独立协议端中的 QQ；要退出平台登录应到协议端操作。
- 微信停止本产品后台读取不等于退出官方微信，也不删除已入库消息；不要删除数据库密钥来“退出登录”。
- 飞书关闭早晚报计划不撤回已发送的消息；撤销应用权限或更换密钥按企业流程操作，之后需重新核对配置及授权。
- Telegram 个人号扩展停止读取后，仍需到官方客户端 **设置 → 设备**结束对应会话才撤销平台 Session；删除或替换本地配置不等于退出旧设备。当前导入版没有连接器 Session 可撤销；原导出文件与已入库内容需按本地保留策略分别处理。
- 所有升级、数据根调整、平台 Session 替换与真实外发均单独确认。不要因读取本部署文档而自动登录、批量导入、启用模型处理或打开自动计划。
