# 微信本地数据库只读接入

关联 FEAT-T06 / CHG-T06-003、CHG-T06-004，2026-11-14。后端 angjustinl，指定审查 joey；前端 joey，指定审查 angjustinl；kirinbao 组织真实账号验收。工程检查与真实验收分别记录。

## 本轮能力

自有 Go 读取器支持显式配置的 Windows 微信 4.x 本地加密库：加载私聊列表、选择一个会话、读取最近双向文本，原子保存到本产品 SQLCipher 消息中心，无需编辑聊天 JSON。微信库以 SQLite `mode=ro` 和 `query_only` 打开，不执行写消息、改已读、迁移、重加密或 checkpoint。SQLite 可能使用 SHM 文件协调 WAL 读取，这不等于修改聊天数据；不生成明文数据库副本。

账号绑定依据操作员明确指定的目录、账号及密钥组合，并辅助检查消息库参与者映射。参与者映射不能单独证明库的拥有者；这不是微信登录认证或在线检测。

## 还没有路径和密钥时

1. 在微信设置的“存储空间／文件管理”查看文件位置，名称随版本变化。定位自己的 `xwechat_files/<账号目录>/db_storage`；不要选择整个磁盘、其他账号或本产品 `data/messages.db`。
2. 账号使用原始 wxid，不填聊天昵称。账号目录可能是 `<wxid>_<4位后缀>`，配置账号时不带这个后缀。
3. 密钥不是微信登录密码、验证码、本产品令牌或产品存储密钥。后台读取器不自动获取密钥；没有密钥时可使用下面的一次性本机初始化入口。

用户报告客户端版本为 **4.1.15.56**，程序会再次核对所选进程实际版本。当前尚未对该用户真实客户端执行挂钩或获取密钥；模拟测试不等于真实兼容性验收。密钥留在本机，不发到聊天或提交 GitHub。

## 微信4.1.15.56首次初始化

需要 Windows、PowerShell7.2+ x64、Python3.13 x64，以及本项目已有的 Go1.26+/GCC 构建环境。项目会使用独立 `.tools/wechat-init-venv`；本轮开发机已准备好该环境，不修改全局Python包。

可以从 Windows 自带 PowerShell5.1 直接运行下列操作入口；入口会查找并验证已有的7.2+ x64后自动调用，不修改当前终端默认版本或执行策略。检查范围包括PATH、常规PowerShell安装目录及当前用户的Codex内置运行时；找不到时才提示安装。PowerShell7与5.1可并存，见[微软文档](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/migrating-from-windows-powershell-51-to-powershell-7)。

首次克隆项目时，先运行依赖准备；它只从官方PyPI安装固定版本和SHA256的Frida包，不连接微信：

```powershell
.\scripts\prepare-wechat-init.ps1
```

随后在项目目录运行（当前是5.1也可）：

```powershell
.\scripts\initialize-wechat.ps1
```

1. 填写自己的 `db_storage` 完整路径和原始wxid；多个微信窗口时明确选择一个。
2. 确认显示的账号、版本及进程。该步骤会使用Frida临时挂钩选定客户端，需要你在本机输入 `INIT <wxid>` 同意后才开始。
3. 等终端显示“准备就绪”，再在微信里**退出登录并重新登录同一个账号**，不要完全退出微信程序。工具不替你操作微信、不提权；换进程或版本不匹配会退出，需要重新发起。
4. 工具仅用所选账号的session.db验证候选密钥；原始采集材料只在有界内存中存在，不打印、不落盘。捕获后先由Go只读探针校验目标库，成功才把完整配置重新封装到当前用户DPAPI文件；失败保留旧配置。已有正式配置默认不覆盖，明确替换时使用 `-Replace`。
5. 看到初始化成功后，重启 `scripts/start-inbox.ps1`，再到消息页手动加载微信私聊。捕获临时密文会清理，正常读取不需要Frida常驻。

仅支持所选当前用户进程与精确版本4.1.15.56；不搜索其他账号、跟随新PID、提供手动挂钩地址或绕过访问限制。Go优先使用系统或项目工具；GCC支持现有MSYS2常见路径，也可用 `-CompilerPath` 明确指定已有gcc.exe。

初始化入口与只读数据库适配器是不同组件：前者临时挂钩客户端，后者只读数据库。MIT离线辅助代码来源见 [第三方说明](../third_party/flandora_wxkey/SOURCE.md)，Frida许可另见 [许可原文](third-party/frida-license.txt)，没有打包完整上游KeyTool或WeFlow。

## 已有密钥后的本机配置

在项目目录运行（入口兼容5.1，会自动调用7.2+）：

```powershell
.\scripts\configure-wechat.ps1
```

按提示输入自己的 `db_storage` 绝对目录、wxid 和 64 位十六进制数据库密钥。密钥输入隐藏；整个配置由当前 Windows 用户 DPAPI 保护，保存在忽略上传的 `data/private/wechat-db.dpapi`，目录限制当前用户访问。已有配置默认不覆盖，确需替换时用 `-Replace`。脚本只保存配置，不提取密钥、不读取聊天。

随后重启后台：

```powershell
.\scripts\start-inbox.ps1
```

启动器会解开本机配置供后台使用，不自动读取聊天。任何 `WECHAT_DB_*` 环境变量已设置时，环境配置整体优先，不与文件混搭。删除或撤销配置后需重启后台。

也可在启动终端自行设置 `WECHAT_DB_DIR`、`WECHAT_DB_ACCOUNT_ID`、`WECHAT_DB_KEY`、可选 `WECHAT_DB_LIMIT`。不自动加载 `.env`；推荐隐藏输入入口，避免密钥进入命令历史。

## 界面操作与范围

消息页找到微信接入面板 → 手动加载私聊 → 核对 wxid → 选择一个会话 → 读取并保存。结果可通过微信筛选、搜索及历史列表查看，已有手动 AI 功能也可使用；读取本身不调用模型。

- 默认检查最近 100 条源记录，最多配置 500 条。窗口含非文本记录，实际文本数量可能更少；界面显示新增、重复、跳过和范围受限。不是全历史读取。
- 来源登记为 `wechatdb`，文件导入仍为 `import`，同账号混用显示 `mixed`。重复读取保留既有本地状态；相同标识内容冲突则整批回滚。
- 原始用户名限域；消息优先使用 server_id，缺失时按分片及 local_id 限定本机身份，不按昵称或正文合并。
- 校验会话库、联系人库和 `message_<n>.db` 分片。读取前后 DB/WAL 身份、长度或时间变化时拒绝该批，待活动停止后手动重试；不承诺全库原子快照或断线自动补漏。
- 配置有效不等于微信版本已通过验证。未知结构、错误密钥、未知发送者或正文解码失败拒绝整批；非文本和超过源存储上限的记录统计跳过，不截断原文。

不包含群聊、公众号、系统会话、媒体本体、语音识别、全历史迁移、后台监听、水位恢复或微信发送。电脑须开机且后台运行；不承诺休眠或关机后读取。

本轮开发验证没有扫描用户磁盘、读取真实聊天或采集真实微信进程内存；初始化真实运行留给用户主动执行。检查证据见 [T06 验证记录](acceptance/T06-wechat-db-validation.md)。指定人员审查与 kirinbao 验收通过前，T06 整项不标记完成。
