# 无人值守收件任务说明

2026-11-18 · `CHG-T06-013` · 产品与验收：kirinbao。本文是当前产品口径；旧文档中的导入、网页入口和预置样本方案保留为历史，不用于无人值守验收。

## 交付目标

用户完成一次账号授权、选定会话范围和提醒计划后，关闭工作台，后台仍能接收之后产生的新消息、去重入库，并按授权生成相关性摘要和提醒。用户每天不需要导入文件、点击同步、打开网页或保持工作台运行。用户回来能看到消息来源、实际处理结果、最后成功时间以及未处理原因。

电脑、后台和平台连接仍须在线，账号失效时如实提示重新授权。收件权限和 AI 分析权限分开；没有分析授权时仍可按收件权限保存消息。重要事项可以提示或生成待办，发送保持关闭。

## 平台现状与取舍

| 数据源 | 目前能做什么 | 主线决定 |
|---|---|---|
| [微信个人号](wechat-db-setup.md#后台持续读取默认关闭) | Windows 本地库已实现授权私聊和群聊的定期只读；只扫描最近窗口，可能漏掉离线或高流量时的记录；真实离场验收待做 | 首个实测渠道：关闭工作台后自动读取一条私聊和一条群聊的新消息；遇到版本、权限、覆盖窗口或读库失败要给出原因 |
| [QQ 个人号](qq-milky-setup.md) | Milky 1.3 已实现授权好友名单的后台事件接收；需本人账号、协议端和本产品后台在线；重启后需重新核验，断线时不保证补齐；真实离场验收待做 | 第二个实测渠道：确认持续新消息接收、重连状态和恢复边界；不把历史按钮或账号核验当作接收成功 |
| [邮箱](email-setup.md) | 已实现 IMAP 按需同步；后台自动增量收件尚未交付 | 后续候选：使用用户授权的邮箱，完成后台调度和增量游标验证后再列为自动接入；购物订单邮件仍归邮箱 |
| [Telegram 个人号](telegram-setup.md) | 已实现选定私聊的只读操作；后台持续收件尚未交付，真实账号和网络权限待验证 | 后续候选：授权和网络都可用时再做后台收件试点，当前不计入自动接入 |
| 闲鱼、淘宝、京东、拼多多个人账号 | 当前办不到自动收取私聊：没有已验证、可持续读取本人私聊的授权通道。现有网址入口和历史文件工具未解决这一问题 | 从自动接入交付清单移除；停止新增手动替代流程。有可验证的平台授权后再重新评估 |
| 购物商家渠道 | 未取得并验证具体店铺的聊天读权限 | 不承诺接入；只有明确店铺角色、权限范围和测试账号后才能启动试点，订单接口不能当聊天读权限 |
| 闪聊 | 产品和授权消息接口尚未确认，当前办不到自动收件 | 暂缓，无可靠证据不排实施 |
