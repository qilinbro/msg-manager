# 购物平台消息接入：参考项目与授权边界

> 整理日期：2026-11-18 · 证据采集：2026-11-17（Asia/Shanghai）
>
> 范围：闲鱼、淘宝旺旺 / 千牛、京东咚咚 / 京麦、拼多多。
>
> 状态：公开资料与源码只读研究；未运行上游项目、未接入真实账号、未进行独立审查或验收。

本专题基于本轮已保存的研究证据整理。仓库存在、星数较高、作者声称实测，都不代表本产品已经具备接入能力。下文将**个人买家、个人卖家和商家客服**分别判断，并区分**聊天正文、订单状态和系统通知**。

## 1. 当前结论与阅读顺序

| 平台 / 身份 | 本轮找到的实现证据 | 对本产品的判断 |
|---|---|---|
| 闲鱼个人账号，主要为卖家接待 | COM-01 及其上游有消息、会话、连接维护代码 | 优先研究消息模型与生命周期；尚非可直接嵌入的只读连接器 |
| 淘宝个人买家 | COM-02 有浏览器内会话和历史消息读取代码 | 可列为小范围授权验证候选；成熟度和页面副作用待验证 |
| 淘宝 / 千牛商家 | 官方机器人与聊天消息服务资料；另有浏览器框架 | 先确认本店铺与应用实际权限，不能用个人网页登录状态替代商家授权 |
| 京东个人买家 | 未找到充分的成熟通用连接器证据 | 保留调研空白，不承诺已经支持，也不据此断言技术上无法接入 |
| 京东商家 / 咚咚插件 | 官方限定场景能力；COM-04 为通用商家浏览器框架 | 只能作为授权评估和交互框架参考，仍需具体店铺适配 |
| 拼多多个人买家 | 已核对的相关实现均面向商家 | 未找到充分的普通买家聊天连接器证据 |
| 拼多多商家客服 | COM-03 有商家长连接、消息队列及历史读取代码 | 可研究接收与历史分页，但不能外推为买家账号支持 |

建议依次阅读 **COM-01 闲鱼消息结构 → COM-02 淘宝买家读取 → COM-03 拼多多商家范围 → COM-04 浏览器框架限制**。这是一份研究顺序，不是实施授权或生产依赖清单。各项目的固定提交与发布快照见第 5 节。

## 4. 官方能力与消息类型的区别

### 淘宝 / 千牛

官方存在[聊天机器人异步下发接口](https://developer.alibaba.com/docs/api.htm?apiId=48631)，但有应用、授权与事件上下文要求。接口名称公开，不代表普通个人账号或本店铺已经拥有完整收发权限。

官方[2021 年旺旺接口下线与升级公告](https://open.alitrip.com/support/announcementDetail.htm?id=25584&source=search)说明旧历史消息、会话关系等 API 下线，并提供聊天消息服务替代方案。该历史公告不能直接证明 **2026 年当前准入条件、收费或申请资格**；实施前须以平台控制台和具体授权为准，不应照用旧 SDK 的接口名称。

### 京东 / 京麦 / 咚咚

[京麦 JSSDK 文档](https://jmw.jd.com/docs/jssdk/jssdk-mobile/api.html)明确限制 `sendDongdongMsg` 在咚咚启动的插件页面中使用，面向当前 Native 聊天用户。这类能力不是通用个人账号服务端接口，也不证明拥有全量聊天接收或历史读取能力。

[官方小程序 API 目录](https://jos.jd.com/apilistnewdetail?apiGroupId=145&apiId=18304&apiName=null)还列有小程序客服与咚咚消息场景，不能外推为所有京东买家聊天。部分官方页面依赖脚本，本轮正文读取有限；保留未核实项，不将目录展示视为权限已开通。

### 拼多多

本轮已核对的公开项目主要围绕商家客服工作台。开放平台官网读取未成功，因此未对其当前正式聊天 API、账号准入或权限范围作肯定或否定判断。COM-03 的商家实现不能替代正式开放平台授权评估。

### 聊天正文、订单与通知应分别验收

| 数据类型 | 应核对的内容 | 不能据此推断的能力 |
|---|---|---|
| 聊天正文 | 账号、会话、消息标识、发送者、方向、原始时间、正文及历史范围 | 能发送、能取其他账号记录、能读完整历史 |
| 订单 / 售后状态 | 授权店铺、订单标识、状态、事件时间及来源 | 能收到买家聊天或代表用户处理订单 |
| 系统 / 营销通知 | 来源、通知类型、目标与授权范围 | 能接管一对一聊天或主动群发 |

现有资料本身也将消息与订单接口分别描述，见 [PDD SDK 功能清单](https://github.com/mf-yang/pdd-customer-service-sdk/blob/92ba11d6baee45c4f8586e90751e2b5c8537c28f/README.md)和[京东订单接口文档](https://jos.jd.com/apilistnewdetail?apiGroupId=55&apiId=14263&apiName=null)。本产品应保留这种来源和类型区别，避免摘要把订单状态误写成人际沟通事实。

## 6. 本产品后续验证边界

本专题没有安装、运行或集成任何上游系统。后续只有明确取得本人账号或店铺授权、核对平台允许范围并完成许可审查后，才进入有界验证。

1. **先确认身份和范围：** 分清买家、卖家、店铺主账号、客服子账号及应用授权；只验证明确选定的账号与会话。
2. **先验收接收与历史：** 核对稳定消息标识、方向、时间、分页覆盖、去重和来源。浏览器打开或切换会话是否改变平台已读，须单独说明。
3. **凭据与模型隔离：** 登录状态只由本机连接层持有，模型不能获取平台凭据。产品限制为只读，不表示底层账号凭据本身只有读取权限。
4. **再评估不在场整理：** 后台运行、会话失效、断线恢复、暂停和限频须有独立验证；本机休眠或关机后不能承诺继续处理。
5. **发送与履约另立边界：** 自动回复默认关闭。发送、退款、付款、确认收货、发货及营销不能随读取功能一并启用；发送结果不确定时保留人工核实状态，不盲目重发。

待补证据包括当前账号权限、许可复核、真实消息样本、页面副作用、历史覆盖、长期运行和指定非作者审查。本专题不改变任务完成统计，正式完成日期仍以项目验收记录为准。
